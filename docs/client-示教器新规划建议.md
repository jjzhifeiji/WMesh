## 2. 新 Client 是什么（人话）

一台已绑定本厂、已读到机械臂号的平板：

1. 人用本厂账号登录；退出或杀进程立刻清钥和明文。
2. 只连本厂（MQTT 控制面 + HTTPS 拉正文），永不连 WAN。
3. 磁盘只有闭包信封；解开的工艺/工程只在内存。
4. 激活恰好一份已授权工程；焊接参数来自闭包里的工艺成员，焊道只认 `processId`。
5. 对机械臂仍走现在这套 8080/8082/8083，时序不改。
6. 离线能焊到节点凭证过期；回连再收意图、再汇事实。

厂租约到期停的是厂服务，不停现场已领钥、凭证未过期的这一焊。

## 3. 建议工程形态

第三工程已就位：`client/` 即 Android 工程根（`applicationId` / `namespace` = `com.gbndt.shijiaoqi`），从 `cloud` 源码迁入，去掉嵌套 git。

```
client/
  app/          现网示教器（Kotlin + Compose）；后续在此换本机袋、登录、MQTT
```

应用内分层，禁止再做成三个近四千行的上帝 ViewModel：

| 层 | 管什么 | 不管什么 |
| --- | --- | --- |
| **平台** | 本机身份、节点凭证、登录会话、MQTT、过站信封、Room+SQLCipher、短码发号 | 焊道几何、Lua 脚本 |
| **资产工作副本** | 登录后内存里解开的工程/工艺；`processId` → 工艺参数 | 落盘明文、文件树 |
| **焊接域** | 点列、包角/多层/T 排几何、脚本生成、暂停续焊 | 身份与下发 |
| **控制器适配** | 老 `SocketManager` 契约（端口、帧、type） | 业务允许/拒绝 |
| **界面** | 老交互：焊道列表、采集、手柄、微调、状态栏 | 直接读磁盘 JSON |

加固与规划一致：`allowBackup=false`；禁止 Keystore 做成开机自动解库；解封钥不准进表、进日志。

## 4. 老能力怎么归堆

### 必须进平台（老项目没有，规划已拍）

- Client 稳定身份、短码 `Cxxxx`、本机钥、厂签发公钥、节点运行凭证
- 本厂账号登录；同一人厂端只留一台登录；换机不远程停焊
- 注册必须读到机械臂识别号并与本机绑死
- MQTT down/up；控制面只推身份/修订/摘要/短命拉取凭据
- 闭包缓存上限、激活一份、完整性校验
- 个人级：本机新建发 `GY-Cxxxx-……` / `GC-Cxxxx-……`，回连汇聚；个人级不得下发到别人的机

### 必须进焊接域（从老项目原样移植）

- 三端口协议与 105/106、Mode/Start 时序
- 单层脚本顺序、附加工艺再跑一遍、WeaveStart 位置
- Pause / RESUME / 断弧再焊 / 中止
- 多层交错与 `executionOffsets`
- 包角生成器、多层坐标系、偏移（含外轴时 `offsetX` 取反）
- 14 套工具、安装姿态、点动方位、速度倍率、手柄键位、在线微调
- 8083 状态解析与报警复位

### 改写后才能进焊接域

- 焊道挂钩：`processPath` → `processId`；禁止工程正文再嵌电流电压
- 元素带 `templateId`，按已收工程模版添加单层 / 多层 / 包角
- 打开工程 = 激活本机袋里那一份闭包，不是打开文件夹
- 选工艺 = 闭包成员下拉，不是逛 `ShiJiaoQi/processes`

### 建议丢掉

- `license.key` + SHA-256(MAC) 注册（改绑机械臂 + 节点凭证）
- 本机全量标准工艺目录 + CDN zip 当真相（改由闭包成员提供）
- 外部存储工程树、`ProcessStorage` 死代码
- 三 Activity 复制粘贴；指令测试可留调试开关，不进正式模式选择
- HTTP 明文更新（发布通道另定，不走现 CDN 当信任根）

### 本机配置（不是资产）

工具坐标、点动方位、速度倍率、外轴开关、手柄伺服：跟机不跟工程，可进本机设置表（仍不得存工艺正文）。不要写进闭包。

## 5. 建议推进顺序（螺旋）

总闸不变：**阶段 3～5 业务未过，不开阶段 6，不向真设备验收。**  
厂端到控制器未开圈前，Client 只允许出规格，不允许当完成物。

| 圈 | 目标 | 验收看什么 | 明确不做 |
| --- | --- | --- | --- |
| **C0 规格** | 把本文未决拍完；冻「平台 / 焊接域 / 丢掉」清单 | 书面条件→允许/拒绝 | 不写 App |
| **C1 本机袋与登录** | Room 信封、SQLCipher、登录领钥、退出清钥、机械臂号登记 | 未登录解不开；拷库无钥打不开；换机旧登录作废但不远程停焊 | 不下发真闭包、不连臂 |
| **C2 通道** | MQTT 订自己的 down；HTTPS 拉闭包；回执；假 Broker 验不出厂签即拒 | 他机 Topic 订不到；低修订不覆盖 | 不焊 |
| **C3 闭包激活** | 缓存上限、激活一份、`processId` 能在内存解到工艺参数 | 缺成员/串版/只拷 → 拒激活 | 不生成 Lua |
| **C4 控制器适配** | 把老 Socket 契约抽成独立模块，用夹具或现控制器打通探活/点动/8083 | 端口与时序与老 APK 一致 | 不改业务身份 |
| **C5 单层作业** | 采集、脚本生成、模拟/起弧/暂停继续、附加槽、手柄 | 与老单层同一时序；工艺来自闭包 | 无多层/T 排 |
| **C6 多层** | 基准路径、层偏移、交错下发 | 与老多层同一几何与 WeaveStart 位置 | — |
| **C7 包角** | 生成器 + 模版字段 | 与老包角点序一致；工艺只引用 | — |
| **C8 T 排** | 第四份工程模版；缝隙切段、打底/盖面只引用 `processId` | 与现网切段/工艺匹配一致 | 不写死 `6T1.2-T排立对接` 文件夹 |
| **C9 个人级与上传** | 本机新建发号、待发队列、点云记录 | 编号不撞；个人级不共享到他机 | 不把个人级当平台级 |
| **阶段 6** | 1 WAN × 2 厂 × 多 Client 端到端 | 在线下发、离线焊、撤销收敛、跨厂拒绝 | 3～5 未业务通过则禁止 |

C4 可与 C1～C3 **并行做适配夹具**（不接本机袋），避免最后才发现控制器时序回归失败。但 C5 起必须已经能从内存闭包读工艺，禁止再读 `processPath`。

## 6. 和现有规格怎么咬合

| 规格 | Client 侧要遵守的 |
| --- | --- |
| 节点通道 | 只连本厂 MQTTS；Topic 按 `factoryId/clientId` 锁死；正文不进 MQTT |
| 正文加密 / 厂端到控制器 | 过站另造 DEK，到站重封；厂库信封不原样拷；进程死必须再登录 |
| 工程与工艺引用 | 焊道/基准/层/附加/包角一律 `processId`；组包仍只认 `deps` |
| 内容模版 | 新建按已收各份模版添加；改正文不套模版；本机袋不另存一份模版原件 |
| 工艺工程编号 | 个人级本机发号；显示编号，钉 UUID |
| 工程闭包 | 不持游离全量工艺库；激活前完整性；焊接中不切换、不撤缓存 |
| 同步审计 | 断网入队；回连幂等；审计无正文、无钥 |
| 不可复制 | 已下发仍不可把平台级正文给人看；列表可留名称/状态/修订/编号 |

老工程导入（`processPath` → 入库身份 → 改写正文）按 `工程与工艺引用.md` §4，应在**厂端或一次性工具**做，不要让现场 App 猜文件名。云端没有文件树，不做自动映射。

## 7. 标准工艺库怎么处理

老项目把 `Standard/` 当全机共享工艺盘，CDN 整包覆盖。这和「Client 只持闭包成员」冲突。

建议（C0 要你点头）：

- **现场不再维护独立标准盘。** 平台级/厂级工艺经工程闭包到达。
- 现有 `StandardProcesses.zip` 一次性导入 WAN 或本厂，变成带 UUID 的工艺资产，再被工程 `deps` 钉死。
- T 排按间隙选打底/盖面：工程正文只存引用规则（或钉多条 `processId`），**不要**再写死文件夹名 `6T1.2-T排立对接`。

过渡期若必须离线带着常用工艺：只能作为「已授权闭包里已经有的成员」，不能再开第三套文件库。

## 9. 风险（写进规格就避开）

- 三个 ViewModel 复制：协议一改漏一侧。C4 必须先抽成唯一控制器适配。
- 过早做焊接 UI 却仍读文件：会把 `processPath` 做回本机袋。C5 门禁 = 内存闭包。
- 把 CDN 标准库继续当真相：闭包完整性形同虚设。
- 用系统备份/Keystore 自动解库：违反厂端到控制器。
- 把老注册码当节点身份：和 WAN 分配、改绑对不上。
- 把 T 排硬塞进单层模版：组包和引用都会脏；必须独立第四份。
- 让现场 App 猜文件名做导入：云端没有文件树。导入只在厂端做。

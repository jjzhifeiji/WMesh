# WMesh 平台架构核心需求

> 单文档基线。只定需求与权威，不定实现。

---

## 1. 是什么

焊接机器人场景的 **WAN + Factory + Client** 分层系统。  
小规模（约 3～5 厂，单厂数十～数百 Robot）、弱网、现场可接触；不是高并发 SaaS。

核心资产（保护与同步对象）：以设备已有明文为准，按类别为 **工艺**（含焊接参数）、**工程**、**点云/图片**、**本地状态**（工具与运行设置、累计统计）、**本地授权**。  
**当前无 Job / Task 模型。**  
工艺业务版本可作后续目标，当前设备明文中不存在；平台须先明确资产的稳定身份与变更语义，具体字段与方式不在本文件规定。

**点云/图片** 暂时只做 **Client 主动上传** 并留下记录；本体落厂内本地 OSS，按核心资产保密。下发、回灌 Client、随工程缓存、WAN 存原件等暂不考虑。

**工件** 是要焊接的物品，有多种不同种类。  
**工程** 针对一次焊接作业，含多条 **焊道**。每条焊道使用多个不同工艺，并带该工程自己的参数（轨迹、多层、包角等）。工艺是可复用配方；工程参数只属于这一份工程，不升格为工艺。
工程须能明确其依赖的工艺；下发、缓存或复制时，不得形成依赖缺失或错配。

**工艺** 与 **工程** 都是有归属的资产，须具备同类治理与元数据（具体字段不定实现），至少包括：


| 项           | 含义               |
| ----------- | ---------------- |
| **所属**      | 归谁（平台 / 厂 / 个人等） |
| **创建人**     | 谁做的              |
| **级别**      | 平台级 / 厂级 / 个人级   |
| **状态**      | 如草稿 / 可用 / 停用    |
| **可复制**     | 可否被上一级复制升档（不改原件） |
| **下发 / 上收** | 谁能下发、谁能上收        |
| **保密**      | 按级别、所属与授权差异化控制   |


二者共用同一套语义，不拆成两套无关模型。差别主要在：**谁做的、谁能下发/上收、可不可复制、保密级别**。

工艺按级别分三档：


| 级别      | 谁制作     | 下发                                 | 上收（复制出新条目，不改原件）                   | 可复制 / 保密             |
| ------- | ------- | ---------------------------------- | --------------------------------- | -------------------- |
| **平台级** | WAN     | 进入**可用**后，按授权下发相关 Factory 与 Client | 不再上收                              | WAN 制作默认可复制为否；控制要求较高 |
| **厂级**  | Factory | 下发该厂 Client                        | 可复制时，WAN 可复制为平台级                  | 制作默认可复制              |
| **个人级** | Client  | 归创建者，不上收则不在厂内共享                    | 可复制时，Factory 可复制为厂级；再经 WAN 可升为平台级 | 制作默认可复制              |


工程同样具备上表各项；下发与缓存按工程份进行，并受级别、所属与授权约束。

可复制只表示允许被上一级复制升档，不是改原件。不可复制的平台级不得因下发而放宽授权与复制限制。

参数名保持行业用语，不另做等级换算或别名。个人级、厂级是汇聚与审计的重点；汇聚不等于共享或升档。

## 2. 硬约束


| 约束                        | 说明                                                      |
| ------------------------- | ------------------------------------------------------- |
| Client 已有本地持久化            | 网络不是运行必要条件，而是同步 / 汇聚 / 策略更新的条件                          |
| Robot 网络极不稳定              | 必须支持离线运行、离线授权、恢复后同步                                     |
| Factory 网络相对可靠            | 厂内管理与汇聚中心                                               |
| Client / Factory 环境不可默认可信 | 可被接触、拷贝、Root；一期重点防止未授权访问、简单复制和跨厂扩散                      |
| 一期接受的风险                   | 有权人员主动泄露、Root 后提取运行态数据、Client 与 Robot 链路抓包及逆向，短期不作为解决目标 |
| 时间不完全信本机                  | 能连通时以上级/服务器时间为准；离线才用本机。Root 或改钟下不承诺强对抗，回连后按双方记录核对并收敛    |
| 数据最小化                     | 低信任节点只持授权范围内必需数据；Client 工程缓存量须可调控（前期可多工程，后期可单工程）        |
| 本文件不定实现                   | 语言、库、中间件、协议等属落地，不在本需求内                                  |

## 3. 分层职责与业务权威

```text
WAN     —— 全局信任 / 跨厂管理 / 全局审计
Factory —— 厂内管理 / 授权策略 / 本地汇聚与审计
Client  —— 独立运行 / 本地状态与数据 / 本地已授权凭证
```

采用 **Client-centric Runtime + Factory-centric Management + WAN-centric Trust**。  
通信层（HTTPS/MQTT/…）只承载交互，不决定业务权威。


| 权威类型         | 谁说了算                          | 冲突时                             |
| ------------ | ----------------------------- | ------------------------------- |
| 运行事实（Fact）   | 产生端 Client，幂等合并               | 追加 / 去重；不按本机墙钟覆盖（时钟可被改）         |
| 管理意图（Intent） | Factory（全局相关由 WAN）            | 上线后 Intent 收敛 Client 本地许可       |
| 信任与跨厂策略      | WAN                           | 约束 Factory 可选项                  |
| 平台级工艺        | WAN 制作与「可用」下发；可由可复制的厂级上收而来    | 各层只读使用，不可改原件                    |
| 厂级工艺         | Factory 制作与厂内下发；可由可复制的个人级上收而来 | 该厂 Client 同步使用；可复制者可被 WAN 升为平台级 |
| 个人级工艺        | Client 制作（Fact）               | 可复制者可被 Factory 升为厂级             |


撤销意图在 Factory；离线期能否继续用，由**授权凭证自身约束**（有效期/范围等）保证，不能假装实时撤销。有效期：在线跟服务器时间，离线才用本机；一期不承诺抵抗 Root 或改钟，回连后核对记录并收敛。

## 4. 数据驻留（原则）


| 位置      | 宜保留                                                          | 不宜默认保留             |
| ------- | ------------------------------------------------------------ | ------------------ |
| Client  | 已授权平台级子集（只读）、本厂已同步的厂级、个人级、按策略缓存的工程与本地状态                      | 超策略的工程、全量平台级库、他厂厂级 |
| Factory | 已下发的平台级、本厂厂级、个人级汇聚（不等于共享或升档）、授权、Client 上传的点云/图片（本地 OSS）及上传记录 | 他厂厂级               |
| WAN     | 平台级主数据、元数据、全局策略、汇总/审计                                        | 点云/图片原件、各厂个人级原件    |


Client 工程缓存量由策略调控（属 Intent）：前期可允许多工程离线缓存，后期可收到单工程。

点云/图片仅 Client 主动上传并记录；大文件与结构化数据分离，本地 OSS 不降低保密要求。下发与回灌不在本期。

## 5. 安全目标（一期现实边界）

安全按保密、完整性、可用性、审计与现场运行均衡，不追求单点过高防护。  
一期重点防止未授权访问、跨厂越权、核心数据被简单复制带走和内容被未授权篡改；支持授权撤销与审计。  
一期接受有权人员主动泄露、Root 后提取运行态数据、Client 与 Robot 链路抓包，不承诺解决这些风险；代码保护 ≠ 数据保护，暂不考虑 TPM。  
Root、改钟等异常若被发现，应留痕并按策略处置，不要求强检测、自动清除或停用节点；不得因保护数据破坏现场运行安全与可用性。  
密钥与数据分离作为防止普通静态复制的原则；具体手法属实现，本文件不定。

---

## 6. 进入实现前的收敛边界

1. 运行权威按 §3 定案，下发只面向授权目标
2. 信任链与身份 / 密钥边界（暂不考虑 TPM）
3. 离线授权（签发 / 本地验证 / 过期 / 撤销 / 更新；接受风险按 §2、§5）
4. 资产的稳定身份与变更语义（不预定 UUID、哈希等实现）
5. 工程与所依赖工艺的一致性要求
6. 内容完整性，以及平台下发、Client 激活与 Robot 本体安全控制的责任边界

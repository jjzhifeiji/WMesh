### 1.3 双网互斥的模拟方式

现场：示教器连厂网时连不到机械臂、焊机和激光；连臂网时连不到厂服，两网不同时通。本机用 `sim_net.sh` 模拟：

| 模式 | 厂端 | 臂 / 焊机 / 激光 | 对应现场 |
|---|---|---|---|
| `factory` | 正常 | 拒绝连接、已连的断开 | 示教器在厂网 |
| `arm` | app 容器 **pause**：请求挂住到超时，与现场无路由一致 | 正常 | 示教器在臂网 |
| `none` | 暂停 | 断开 | 切网过程中 / 都断 |
| `both` | 正常 | 正常 | 仅调试用，现场不会出现 |

> **差异说明**：现场示教器在臂网上会判定 `armNetOnly`（臂已连上、本机在臂网段、厂服不在本机任何网段），然后**立即跳过**所有厂服请求。本机全在一个网段，`armNetOnly` 不成立，厂服请求会**等到超时**再失败。所以本机能验证「厂服不通时功能不受影响、回网后补齐」，验证不了「立即跳过、不等待」；后者由单测 `RobotLanTest`、`BagSessionWeakNetTest` 覆盖，并在 §12 真机项复核。

> **副作用**：`arm` 和 `none` 暂停的是整个厂端 app，厂端到 WAN 的保活、租约续期也一起停了。停得久了，WAN 会把本厂标成离线，再久会触发租约到期（E-02），双网用例会被这些异常串扰。所以：
> - 单条 N 用例在 `arm` 下停留尽量控制在 10 分钟内；需要更久的（如 N-20 的 TTL）把 TTL 调短。
> - **每条用例结束都执行 `sim_net.sh both` 复原**；用例中途失败也要复原，否则后续用例全部受影响。开始执行前先跑一次 `sim_net.sh both`。

### 1.6 环境注意事项（2026-11-03 测试后补充）

**日志转发风险（必做）**：WAN 和厂端两个 `docker-compose.yml` 里 `LOKI_URL` 默认指向共享环境 `http://154.82.81.16:3100/loki/api/v1/push`，不改的话本机 alloy 会把测试日志（含示教器日志）推到共享环境，污染别人的数据。上一轮就这样推过去约 9.8 万条。所以：

1. 执行前把 `LOKI_URL` 指向本机 Loki 或一个连不上的地址，例如：
   ```bash
   export LOKI_URL=http://127.0.0.1:9/loki/api/v1/push
   ```
2. 每次 `init.sh` 跑完，再停掉两端的 alloy 容器（`docker compose stop alloy`，WAN、厂端各一次）。
3. I-16（日志）要测时，单独起本机 Loki 再开 alloy，测完再停。

**登录环境**：示教器扫描会列出别人地址上的同名厂（如 154.82.81.16、其它同事的机器），登录时只选本机网卡地址那一条，不要登录其它环境。

**只断线激光、不断臂**：假控制器没有「只断激光」的命令（`link off` 臂和激光一起断，`laser on/off` 只改寄存器，`mute` 只停 8083）。目前拆成两个进程跑：

```bash
# 主进程：臂、焊机、控制口，不带激光
python3 client/ShiJiaoQi-New/scripts/fake_robot.py
# 激光专用实例：只监听 :502，日志另写
python3 client/ShiJiaoQi-New/scripts/fake_robot.py --base-port 9180 --laser-host 0.0.0.0
```

要断激光时只杀第二个进程，臂一直「已连接」；重起它就恢复。建议后续给假控制器加 `laser off`（只断 :502 连接）命令。

**平板输入**：

- 讯飞输入法会乱改大小写、吞数字，长串要一个字一个字输；需要大量数字的项（C-25、C-40）预留时间。
- 全屏输入法会盖住对话框，先按返回键收起输入法，再点对话框按钮。
- Toast 不在 uiautomator 树里，判定提示文案要看 App 日志（或截图）。

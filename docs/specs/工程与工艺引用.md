## 底线

工程里跟工艺有关的，只有**引用**。电流、电压、速度、起收弧、摆动属于工艺正文，不得嵌进工程。

工艺是独立资产（稳定 UUID）。工程 `deps` 钉死用哪几条、哪一修订，由参数里的工艺引用带出，新建不必另填。工程正文只写哪条焊道用哪条工艺。文件路径、显示名不当身份。

---

## 1. 两层，不得两套真相

| 层 | 落在哪 | 管什么 | 形态 |
| --- | --- | --- | --- |
| **依赖** | 工程资产的 `deps`（不是正文 JSON） | 组包、删除保护、升档 | `[{id, revision, digest}, ...]`；工艺的 `deps` 必须空 |
| **正文** | 工程内容 JSON | 哪条焊道/多层/包角/附加用哪条已声明的工艺 | `processId` = 某条 dep 的身份 |

组包成员恰好是：工程自己 + `deps` 声明的每一条工艺。不得多塞未声明的，也不得少塞已声明的。  
Client 不持游离全量工艺库，只持闭包里的工艺成员。列表看名称/状态/修订可不解开工艺正文；焊接参数必须解才用。

谁可以依赖哪一级，仍按资产治理：个人级可钉自己的个人工艺或本厂厂级；厂级可钉本厂可用厂级、个人级以及已到达的平台级；平台级只钉平台级。草稿、停用不得被新依赖，下拉也不展示。工艺升修订后，已存工程仍钉旧修订，要跟上必须显式改工程。

---

## 2. 工艺正文有什么（工程里不该出现这些）

工艺 JSON 是一份参数对象。旧文件没有 `id`；入库后身份在资产行上，不写进这份 JSON。

| 字段 | 含义 |
| --- | --- |
| `name` | 显示名，不当身份 |
| `offsetX` / `offsetY` / `offsetZ` | 焊枪偏移 |
| `current` / `voltage` / `speed` | 电流、电压、速度 |
| `startArcTime` / `startArcCurrent` / `startArcVoltage` | 起弧 |
| `endArcTime` / `endArcCurrent` / `endArcVoltage` | 收弧 |
| `oscillation` | 摆动（等待、频率、振幅、左右停、侧长、过零、回摆比、方位角、倾角） |

---

## 3. 工程正文里挂钩工艺的位置

工程根是焊缝数组。每个元素带 `templateId`，套那一份工程模版自己的对象字段。点列、位姿、关节角、多层偏移、完成/启用标记是工程自己的，不是工艺。

### 3.1 旧形态（不当目标）

`processPath` 指向工艺文件名或相对路径（如 `1焊角6.5mm以下.json`、`User/1K6.5mmD.json`）。可空。多层每道还内嵌整份工艺对象，样例里经常是 `{}`。

| 位置 | 旧字段 | 样例出处 |
| --- | --- | --- |
| 单层焊道 | `processPath` | `project_data.json` |
| 多层基准路径 | `basePath.processPath` | `multilayer_data.json` |
| 多层每道 | `passes[].process`（整份工艺参数） | 同上，多为空对象 |
| 附加工艺 | `extraProcesses[].processPath` | 单层「第七轴」 |
| 包角 | `cornerGroupParams.processPath` | 单层「第八轴」；默认内容模版尚未收这个字段 |

工艺槽走 `processId`（或类型为工艺的字段）。厂端以已收各份对象根副本为准；还没有副本时新建正文原样，收集引用用空库三份明细。

### 3.2 目标形态

上表旧字段一律改成引用，禁止路径，禁止内嵌参数：

| 位置 | 目标字段 | 约束 |
| --- | --- | --- |
| 单层焊道 | `processId` | 空=该焊道未选工艺；有值必须能钉进本工程 `deps` |
| 多层基准路径 | `basePath.processId` | 同上 |
| 多层每道 | `passes[].processId` | 取代 `passes[].process` 对象 |
| 附加工艺 | `extraProcesses[].processId` | `extraProcesses[].id` 仍是附加条目自己的身份，不是工艺身份 |
| 包角 | `cornerGroupParams.processId` | 收入模版时同样只引用 |

同一条工艺可以被多条焊道引用；`deps` 里只出现一次。正文不得再写 `processPath`，也不得再写电流电压。

---

## 4. 导入旧样例

1. 每份工艺文件先入库，得到稳定身份、修订、摘要。  
2. 工程里出现过的每条 `processPath`（含附加、包角、基准路径）映射成该身份。  
3. 去重写入工程 `deps`（当时修订与摘要）。  
4. 工程正文上述位置改写成 `processId`，删掉路径和内嵌 `process` 对象。  
5. 空路径保持空引用，不进 `deps`。

---

## 5. 不做

- 不把 `processPath`、工艺文件名、显示名当稳定身份。  
- 不在工程正文里复制一份工艺参数。  
- 不因工程已下发就把不可复制工艺改成可复制。  
- 不自动随工艺升修订改工程 `deps`。  
- 升档或复制工程时不得另生成工艺身份。

---

## 6. 已决（云端本圈）

1. 写工程时服务端强制 `processId` ⊆ `deps`（空引用除外）。新建按参数把引用写入 `deps`。  
2. 空库落下三份独立工程模版（各带当前字段明细）。新建从空字段起。不启动自动改已手改过的模版。

---

## 7. 云端怎么落地（WAN）

只动 `global/`。不改厂端 `Default()`、厂端 UI、控制器、旧文件导入。组包、删除保护、升档许可、审计动作名仍按阶段 3～4。

### 7.1 已经有的，不要重做

| 能力 | 现状 |
| --- | --- |
| 工程 `deps` | 新建、升档已校验：必须是平台级可用工艺，修订与摘要对上 |
| `SetPlatformProjectDeps` | 应用服务已有；**没有 HTTP**，管理台改不了依赖 |
| 组包 | 只认 `deps`，不读焊道字段 |
| 升档工程 | `deps` 按源身份改写成已升档平台级；**正文原样拷**，焊道里若已是厂级 `processId` 会对不上 |
| 套模版 | 只 `Create*` 套；改正文 / 复制 / 升档 / 改模版都不改已有 JSON |
| 工艺模版 | 已是参数对象，无 `id`，本圈不动 |
| 管理台 | 新建工程不另选依赖；正文编辑器按模版当普通文本，会把 `processPath` 当路径填 |

### 7.2 本圈改什么

1. **工程模版**每份独立：名称、对象字段表、修订；工艺表不动。  
2. **空库**落下三份（单层焊道 / 多层焊缝 / 包角）各带当前字段；之后新建从空字段起。  
3. **写工程**时按各份自己的字段表收集 `processId`；新建写入 `deps`，改正文仍须 ⊆ `deps`。  
4. **升档工程**时按当前各份字段表改写正文 `processId`，对照表与 `deps` 相同；不套模版、不改其它字段。  
5. **HTTP** 仍可改依赖；管理台新建不另选依赖，焊道上的工艺从已发布工艺里选，禁止填路径。

### 7.3 工程模版字段

每份自己的对象字段表。空库三份带上现在的明细（单层含附加工艺槽，多层含基准路径与各层，包角含单层字段加包角几何）。之后新建不预填字段。

工艺槽只写 `processId`（类型 `process` 或旧键名）。禁止 `processPath`，禁止嵌套工艺参数对象。

新建工程套用后是 `[]`；添加一条只套那一份字段。

已落库的工程正文**不批处理**。改某一份只升高该份修订并下发；已有平台级工程仍可带着旧 `processPath` 活着。云端没有「文件名 → 身份」对照，§4 导入不做。

### 7.4 写工程

按**当前各份自己的字段表**收集工艺槽（旧模版键 `processId` 的文本仍算）。该份字段里没有的槽不当引用。新建把非空引用写入 `deps`（可沿用调用方多带的）。改正文时任一非空值不是本行 `deps` 的身份 → 拒绝，原件不变。空字符串不算引用。

落点：`CreatePlatformProject`（套模版之后从参数补 `deps`）、`UpdatePlatformAssetContent`（不套模版，仍按当前模版扫引用 ⊆ `deps`）、`SetPlatformProjectDeps`（改依赖后旧正文仍须 ⊆ 新 `deps`）。工艺、非 JSON 旧测试正文：套完后没有非空引用则通过。组包仍只认 `deps`。

### 7.5 升档改写引用

厂级工程升平台级时，先按现逻辑把 `deps` 改成平台级身份。再按当前工程模版改写正文里每个非空工艺引用；找不到（工艺还没升档）→ 依赖错配，与现在升档失败同一口径。其它键不动，不套模版。

摘要改按**改写后**正文计算。再升是否跳过：对这份快照做同样改写，摘要相同则跳过，避免「厂级正文没变、平台级因改写永远对不上」。已送达厂端的旧闭包快照仍不动。

这不是另生成工艺身份，只是指针跟着 `deps` 改写。

### 7.6 HTTP 与管理台

- `POST /v1/assets/{assetId}/deps`：调已有 `SetPlatformProjectDeps`。  
- 新建工程：不另选依赖；按命名模版一条条添加；工艺槽下拉已发布平台工艺，可空。禁止自由输入路径。  
- 工程模版页对每份独立新建/编辑/删除（名称 + 字段表），立刻生效并下发；每份自己的修订；不要导出、导入、恢复默认、整页保存。  
- 不改列表、发布、停用、从工厂升档的入口；升档在服务端做 §7.5。

### 7.7 验收（`global/server` 应用服务 + 管理台）

1. 空库三份独立工程模版；工艺槽都是 `processId`；没有 `processPath`；无嵌套工艺对象。  
2. 空库新建工程：落库正文为 `[]`；按某份添加则只有该份字段；空引用不进 `deps`。参数里选了工艺则写入 `deps`。  
3. 改一份工程模版名称或字段：只升这一份修订；已有平台级工程正文与修订不变。  
4. 该份字段上的 `processId` 不是可用平台工艺 → 新建拒绝；改正文 / 改依赖后不在 `deps` → 拒绝；字段里没有的槽不当引用。  
5. 升档工程：`deps` 与模版内 `processId` 都是平台级身份；工艺未先升档 → 拒绝；源正文未变再升 → 跳过。  
6. 组包成员仍恰好是工程 + `deps`，不因正文引用增减成员。  
7. 非管理员改模版 / 改平台工程 → 拒绝。

### 7.8 本圈明确不做

- Client / 本机袋。  
- 把旧 `processPath` 自动映射成身份（云端无文件树；厂端导入仍按 §4，本圈不做批处理）。  
- 改正文套模版；批改已有资产；随工艺升修订改 `deps`。  
- 把模版当焊接资产升档。

厂端圈见 §8。

## 8. 厂端怎么落地

只动 `factory/`。组包、删除保护、升档许可仍按阶段 3～4。厂端不改 WAN 模版原件。

1. **工程模版**按身份收各份对象字段表最高修订；没有对象根副本时新建正文原样。收集引用：有副本按各份字段，没有则用空库三份明细。  
2. **写工程**：新建从参数收集工艺引用写入 `deps`；改正文仍须 ⊆ `deps`。  
3. **HTTP** `GET /v1/factories/{id}/project-templates` 列已收各份；`POST .../deps` 仍调 `SetProjectDeps`。  
4. **管理台**新建不另选依赖；按已收模版名添加焊缝；焊道工艺下拉选已发布工艺（厂级/已到平台级；个人工程还可选自己的个人工艺）。不另开工程模版页。

升个人级为厂级不改写 `processId`。不得改副本，不在厂端做「恢复默认」。

### 8.1 验收（`factory/server` 应用服务 + 管理台）

1. 已收对象根工程模版后新建：按份套用，元素带 `templateId`；工艺槽是 `processId` 或类型为工艺的字段。  
2. 无副本时新建：正文原样；空工程为 `[]`。  
3. 对得上的 `processId` 不是可用工艺 → 新建拒绝；改正文 / 改依赖后不在 `deps` → 拒绝。  
4. 收到更高修订后，已有正文不变；之后新建才套。  
5. 组包成员仍恰好是工程 + `deps`。

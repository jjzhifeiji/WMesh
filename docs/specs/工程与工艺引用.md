## 底线

工程里跟工艺有关的，只有**引用**。电流、电压、速度、起收弧、摆动属于工艺正文，不得嵌进工程。

工艺是独立资产（稳定 UUID）。工程 `deps` 钉死用哪几条、哪一修订；工程正文只写哪条焊道用哪条已声明的工艺。文件路径、显示名不当身份。

---

## 1. 两层，不得两套真相

| 层 | 落在哪 | 管什么 | 形态 |
| --- | --- | --- | --- |
| **依赖** | 工程资产的 `deps`（不是正文 JSON） | 组包、删除保护、升档 | `[{id, revision, digest}, ...]`；工艺的 `deps` 必须空 |
| **正文** | 工程内容 JSON | 哪条焊道/多层/包角/附加用哪条已声明的工艺 | `processId` = 某条 dep 的身份 |

组包成员恰好是：工程自己 + `deps` 声明的每一条工艺。不得多塞未声明的，也不得少塞已声明的。  
Client 不持游离全量工艺库，只持闭包里的工艺成员。列表看名称/状态/修订可不解开工艺正文；焊接参数必须解才用。

谁可以依赖哪一级，仍按资产治理：个人级可钉自己的个人工艺或本厂厂级；厂级钉本厂厂级（已到达的平台级工艺也可）；平台级只钉平台级。草稿、停用不得被新依赖。工艺升修订后，已存工程仍钉旧修订，要跟上必须显式改工程。

---

## 2. 工艺正文有什么（工程里不该出现这些）

工艺 JSON 是一份参数对象。旧文件没有 `id`；入库后身份在资产行上，不写进这份 JSON。

| 字段 | 含义 |
| --- | --- |
| `name` | 显示名，不当身份 |
| `offsetX` / `offsetY` / `offsetZ` | 焊枪偏移 |
| `current` / `voltage` / `speed` | 电流、电压、速度 |
| `startArcTime` / `startArcCurrent` / `startArcVoltage` | 起弧 |
| `endArcTime` / `endArcCurrent` / `endArcVoltage` | 收弧 |
| `oscillation` | 摆动（等待、频率、振幅、左右停、侧长、过零、回摆比、方位角、倾角） |

---

## 3. 工程正文里挂钩工艺的位置

工程根是焊缝数组。点列、位姿、关节角、多层偏移、完成/启用标记是工程自己的，不是工艺。

### 3.1 旧形态（不当目标）

`processPath` 指向工艺文件名或相对路径（如 `1焊角6.5mm以下.json`、`User/1K6.5mmD.json`）。可空。多层每道还内嵌整份工艺对象，样例里经常是 `{}`。

| 位置 | 旧字段 | 样例出处 |
| --- | --- | --- |
| 单层焊道 | `processPath` | `project_data.json` |
| 多层基准路径 | `basePath.processPath` | `multilayer_data.json` |
| 多层每道 | `passes[].process`（整份工艺参数） | 同上，多为空对象 |
| 附加工艺 | `extraProcesses[].processPath` | 单层「第七轴」 |
| 包角 | `cornerGroupParams.processPath` | 单层「第八轴」；默认内容模版尚未收这个字段 |

内容模版（`contenttpl` 默认工程表）WAN 与厂端都已改成 `processId`。生产厂端仍以已收副本为准；空库/测试夹具走代码 `Default()`。

### 3.2 目标形态

上表旧字段一律改成引用，禁止路径，禁止内嵌参数：

| 位置 | 目标字段 | 约束 |
| --- | --- | --- |
| 单层焊道 | `processId` | 空=该焊道未选工艺；有值必须是本工程 `deps` 里的身份 |
| 多层基准路径 | `basePath.processId` | 同上 |
| 多层每道 | `passes[].processId` | 取代 `passes[].process` 对象 |
| 附加工艺 | `extraProcesses[].processId` | `extraProcesses[].id` 仍是附加条目自己的身份，不是工艺身份 |
| 包角 | `cornerGroupParams.processId` | 收入模版时同样只引用 |

同一条工艺可以被多条焊道引用；`deps` 里只出现一次。正文不得再写 `processPath`，也不得再写电流电压。

---

## 4. 导入旧样例

1. 每份工艺文件先入库，得到稳定身份、修订、摘要。  
2. 工程里出现过的每条 `processPath`（含附加、包角、基准路径）映射成该身份。  
3. 去重写入工程 `deps`（当时修订与摘要）。  
4. 工程正文上述位置改写成 `processId`，删掉路径和内嵌 `process` 对象。  
5. 空路径保持空引用，不进 `deps`。

---

## 5. 不做

- 不把 `processPath`、工艺文件名、显示名当稳定身份。  
- 不在工程正文里复制一份工艺参数。  
- 不因工程已下发就把不可复制工艺改成可复制。  
- 不自动随工艺升修订改工程 `deps`。  
- 升档或复制工程时不得另生成工艺身份。

---

## 6. 已决（云端本圈）

1. 写工程时服务端强制 `processId` ⊆ `deps`（空引用除外）。  
2. 已有库用管理台「恢复默认」后保存下发；空库走代码 `Default()`。不启动自动改手改过的模版。

---

## 7. 云端怎么落地（WAN）

只动 `global/`。不改厂端 `Default()`、厂端 UI、控制器、旧文件导入。组包、删除保护、升档许可、审计动作名仍按阶段 3～4。

### 7.1 已经有的，不要重做

| 能力 | 现状 |
| --- | --- |
| 工程 `deps` | 新建、升档已校验：必须是平台级可用工艺，修订与摘要对上 |
| `SetPlatformProjectDeps` | 应用服务已有；**没有 HTTP**，管理台改不了依赖 |
| 组包 | 只认 `deps`，不读焊道字段 |
| 升档工程 | `deps` 按源身份改写成已升档平台级；**正文原样拷**，焊道里若已是厂级 `processId` 会对不上 |
| 套模版 | 只 `Create*` 套；改正文 / 复制 / 升档 / 改模版都不改已有 JSON |
| 工艺模版 | 已是参数对象，无 `id`，本圈不动 |
| 管理台 | 新建工程另选依赖；正文编辑器按模版当普通文本，会把 `processPath` 当路径填 |

### 7.2 本圈改什么

1. **默认工程表**（`global/.../contenttpl` 的 `defaultProject`）按 §3.2 改引用；工艺表不动。  
2. **空库** `ensureTemplate` 写入新默认。已有库不静默改已手改过的模版。  
3. **写工程**时按当前工程模版收集 `processId`（强制 ⊆ `deps`）。  
4. **升档工程**时按当前工程模版改写正文 `processId`，对照表与 `deps` 相同；不套模版、不改其它字段。  
5. **HTTP** 补改依赖；管理台焊道上的工艺从已声明依赖里选，禁止填路径。已有库换新默认：工程模版页「恢复默认」后保存。

### 7.3 默认工程表

| 位置 | 现在 | 改成 |
| --- | --- | --- |
| 焊缝 / `basePath` / `extraProcesses[]` | `processPath` 文本 | `processId` 文本，默认 `""` |
| `passes[]` | `process` 对象（嵌整份工艺字段） | `processId` 文本，默认 `""` |
| `cornerGroupParams` | 模版里没有 | 收入对象；工艺槽只收 `processId` |

包角几何按设备明文一并收入，避免新建套用时被当多余键删掉：`groupId`、`refPathAId`、`refPathBId`、`layerCount`、`initialLength`、`upwardOffset`、`lengthReduction`、`isMaster`、`torchRx` / `torchRy` / `torchRz`。不是工艺正文。

`extraProcesses[].id` 仍是附加条目自己的身份。

已落库的工程正文**不批处理**。改模版只升高模版修订并下发厂端；已有平台级工程仍可带着旧 `processPath` 活着。管理台按新模版点保存，会丢掉模版外的键（含路径和内嵌参数），须人重选 `processId`；云端没有「文件名 → 身份」对照，§4 导入不做。

已有库换新默认：管理台「恢复默认」后保存。手改过字段表的，不覆盖。

### 7.4 写工程

按**当前工程模版**收集键为 `processId` 的文本字段（不是写死焊道五处）。模版加一处引用，校验和表单都跟上；模版里没有的 `processId` 不当引用。任一非空值不是本行 `deps` 的身份 → 拒绝，原件不变。空字符串不算引用。`deps` 允许有未被焊道用到的工艺（组包仍带上）。

落点：`CreatePlatformProject`（套模版之后）、`UpdatePlatformAssetContent`（不套模版，仍按当前模版扫引用）、`SetPlatformProjectDeps`（改依赖后旧正文仍须 ⊆ 新 `deps`）。工艺、非 JSON 旧测试正文：套完后没有非空引用则通过。组包仍只认 `deps`。

### 7.5 升档改写引用

厂级工程升平台级时，先按现逻辑把 `deps` 改成平台级身份。再按当前工程模版改写正文里每个非空 `processId`；找不到（工艺还没升档）→ 依赖错配，与现在升档失败同一口径。其它键不动，不套模版。

摘要改按**改写后**正文计算。再升是否跳过：对这份快照做同样改写，摘要相同则跳过，避免「厂级正文没变、平台级因改写永远对不上」。已送达厂端的旧闭包快照仍不动。

这不是另生成工艺身份，只是指针跟着 `deps` 改写。

### 7.6 HTTP 与管理台

- `POST /v1/assets/{assetId}/deps`：调已有 `SetPlatformProjectDeps`。  
- 新建 / 编辑工程：依赖仍多选已发布平台工艺；模版里键为 `processId` 的字段做成下拉，选项 = 当前 `deps`，可空。禁止自由输入路径。  
- 工程模版页加「恢复默认」：把字段表设成代码 `Default(project)`，保存后升高修订并下发。  
- 不改列表、发布、停用、从工厂升档的入口；升档在服务端做 §7.5。

### 7.7 验收（`global/server` 应用服务 + 管理台）

1. 新默认工程表：五处都是 `processId`；没有 `processPath`；`passes[]` 无嵌套工艺对象；包角对象在且工艺槽是 `processId`。  
2. 空库新建工程：落库正文已套新表；空引用保持空，不进 `deps`。  
3. 改模版加无关字段：已有平台级工程正文与修订不变。  
4. 当前模版里的 `processId` 不在 `deps` → 新建 / 改正文 / 改依赖都拒绝；模版外的同名键不当引用。  
5. 升档工程：`deps` 与模版内 `processId` 都是平台级身份；工艺未先升档 → 拒绝；源正文未变再升 → 跳过。  
6. 组包成员仍恰好是工程 + `deps`，不因正文引用增减成员。  
7. 非管理员改模版 / 改平台工程 → 拒绝。

### 7.8 本圈明确不做

- Client / 本机袋。  
- 把旧 `processPath` 自动映射成身份（云端无文件树；厂端导入仍按 §4，本圈不做批处理）。  
- 改正文套模版；批改已有资产；随工艺升修订改 `deps`。  
- 把模版当焊接资产升档。

厂端圈见 §8。

## 8. 厂端怎么落地

只动 `factory/`。组包、删除保护、升档许可仍按阶段 3～4。厂端不改 WAN 模版原件。

1. **默认工程表**与 WAN 对齐：`processId`，无路径、无嵌套工艺对象，包角在。  
2. **写工程**按当前工程模版收集 `processId` ⊆ `deps`：有已收副本用副本，没有则用代码 `Default()`。  
3. **HTTP** `POST /v1/factories/{id}/assets/{assetId}/deps` 调已有 `SetProjectDeps`。  
4. **管理台**焊道工艺按下拉选已发布工艺（厂级/已到平台级；个人工程还可选自己的个人工艺），身份字段自动生成不手填。

升个人级为厂级不改写 `processId`（身份仍是本厂的）。不在厂端做「恢复默认」。

### 8.1 验收（`factory/server` 应用服务 + 管理台）

1. 新默认工程表：五处都是 `processId`；没有 `processPath`；`passes[]` 无嵌套工艺对象。  
2. 无副本时新建：按代码默认表扫引用；空引用保持空。  
3. 当前模版里的 `processId` 不在 `deps` → 新建 / 改正文 / 改依赖都拒绝。  
4. 收到更高修订工程模版后，之后新建才套新处引用。  
5. 组包成员仍恰好是工程 + `deps`。

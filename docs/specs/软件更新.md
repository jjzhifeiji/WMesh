# 软件更新：厂服务包与客户端包

> 讨论已拍板；工程冻结见 `软件更新-工程冻结.md`。服务层矩阵未跑通前不得当完成物。  
> 依据 `docs/平台架构核心需求.md` §2、§3、§5、§6、§7.1：Client 只连本厂；下发只面向授权目标；焊接进行中不中断。  
> 通道形态复用 `节点通道.md`（控制面小信封 + HTTPS 拉正文）。不改阶段 1～5 的资产允许/拒绝、归属与审计。  
> 不改核心需求正文。

---

## 底线（无先后）

同时成立：

- **软件包不是工艺/工程。** 不进资产表，不走可复制、升档、闭包组包。
- **云端只发到厂，平板只从本厂拉。** Client 永不连 WAN；丢掉老 CDN 明文更新。
- **所有安装必须人确认。** 到包 ≠ 安装。无人确认则继续跑旧版本。
- **只向前。** 不允许下发或安装比当前已接受版本更低的包；坏包靠再发更高版本补丁。

---

## 1. 本圈目标

WAN 管理员发布两类更新包，按厂下发：

| 种类 | 现在是什么 | 谁安装 |
| --- | --- | --- |
| **厂服务包** | 本厂 Docker 镜像（API + 管理台 + Flyway 脚本） | 本厂超管在管理台确认后，换镜像重启；启动时只向前迁库 |
| **客户端包** | 当前是 Android APK | 该平板当前登录的人点确认后，走系统安装器 |

厂端先验签、校验摘要，把包落到本厂对象存储。厂服务不自动重启。平板不自动覆盖。

验收看：未确认不装、低版本拒绝、他厂拿不到、焊接中点确认也拒绝、摘要不对原件不动。

---

## 2. 本圈不做

不改工艺/工程身份与闭包。不建 Client 工程、不向 Robot 下指令。不做 WAN 自身升级。不静默装、不强制装、不把旧版当回滚通道。不把更新包当加密工艺正文（包本身要防篡改，不走租约解封）。厂库与对象存储数据不随服务包覆盖。

---

## 3. 包是什么

一份发布是一条只向前的版本，不是资产修订。

| 项 | 含义 |
| --- | --- |
| **种类** | `factory_service` 或 `client_apk` |
| **版本** | 单调整数，只比较这个；另有给人看的版本名 |
| **摘要** | 包文件 SHA-256；对不上不得提示、不得装 |
| **签名** | WAN 签发；厂端先验这层，再给本厂 Client 另签就绪信封 |
| **字节** | 原样过站，厂端不得改包再转发给平板 |

同一（种类, 版本）再下发到同一厂 → 允许且幂等，仍是那一份。  
已有更高版本待确认或已安装时，再来更低版本 → 拒绝；未确认的低版本提示作废，改提示更高那份。

---

## 4. 怎么走（两跳同形）

```text
WAN 管理员上传并按厂下发
  → MQTT 小指令（种类、版本、摘要、目标厂）
  → 厂 HTTPS 拉到本厂对象存储，验签验摘要
  → 厂服务包：管理台弹窗，超管确认后安装并重启厂服务
  → 客户端包：MQTT 就绪信封到已绑定平板；平板可先拉包校验，安装必须等人确认
```

控制面不塞 APK/服务包全文。短命拉取凭据只给已授权本厂节点。

平板只连本厂 MQTTS + 本厂 HTTPS。假 Brokers 签不出本厂就绪信封；摘要对不上不装。

---

## 5. 谁允许做什么

| 谁 | 允许 | 拒绝 |
| --- | --- | --- |
| **WAN 管理员** | 上传两类包、按已认领厂下发、看送达/待确认/已安装 | 替厂或替平板点确认；把包发到未认领/他厂冒名目标 |
| **本厂超管** | 管理台看到待确认的厂服务包并确认安装；看到本厂已收的客户端包（供平板来拉） | 改包字节；把包转给他厂；不确认就当已安装 |
| **本厂其他角色** | 无 | 确认厂服务更新 |
| **平板当前登录的本厂有效账号** | 看到本机待确认的客户端包并确认安装 | 未登录安装；替他机确认；连 WAN 拉包 |
| **其他人 / 他厂** | 无 | 读、拉、装 |

没有明确许可一律拒绝。WAN 通道只把包送到目标厂；安装权威在当场点确认的那个人。

---

## 6. 确认与安装

**共同：**

- 包未完整到达、签名失败、摘要不符 → 不弹窗，原运行版本不动，留痕。
- 弹窗必须能看：种类、版本名、版本号。确认前不替换正在跑的程序。
- 点「暂不更新」或关掉弹窗 → 不装；下次进入管理台 / 下次打开 App 仍提示，直到装上或被更高版本顶替。
- 确认后安装失败 → 继续跑旧版本，允许再确认；不得自行改去装更低版本。

**厂服务：**

- 仅本厂超管在厂端管理台弹窗确认。无人在线则包停在「待确认」，下次超管登录再弹。
- 确认后换 Docker 镜像并重启厂服务；启动时按 Flyway **只向前**迁库。PostgreSQL 业务数据与本厂对象存储不覆盖、不 down、不回滚。
- 重启会短暂断开本厂管理与通道；**不得因此远程停掉现场正在焊的 Client**。凭证未过期的这一焊继续。

**平板：**

- 不强制。当前登录者点确认才走系统安装器。
- 焊接进行中即使点确认 → 拒绝安装，提示焊完再确认。
- 各机各自确认，允许一厂暂时多版本并存。
- 节点凭证过期不得新装；已在焊的不因过期中断。

---

## 7. 驻留

- **WAN**：发布原件、向哪些厂下发、送达回执。不持厂内确认人明细以外的厂内人员库。
- **厂**：已收包的（种类, 版本）只读副本 + 对象存储字节；厂服务是否已确认安装；不把他厂包当已到达。
- **平板**：只持已向本机就绪的客户端包；不得缓存全厂服务包、他机包、WAN 地址。

源侧后来再发更高版本，已安装的旧版本不自动覆盖，必须再提示、再确认。

---

## 8. 允许 / 拒绝

1. **未确认**：包已送达 → 允许驻留；安装拒绝。
2. **超管确认厂服务**：摘要与签名通过 → 允许替换并重启；库与 OSS 不动。
3. **非超管确认厂服务** → 拒绝。
4. **WAN 替厂确认** → 拒绝。
5. **平板确认且空闲** → 允许走系统安装器。
6. **平板焊接中确认** → 拒绝；当前版本不动。
7. **未登录平板安装** → 拒绝。
8. **低版本**：已接受更高版本后下发或安装更低 → 拒绝。
9. **同版本再下发同一厂** → 允许，幂等。
10. **摘要不符或签名失败** → 拒绝提示与安装；原件不动。
11. **他厂 / 未授权厂** → 不得出现副本。
12. **平板直连 WAN 或旧 CDN** → 拒绝（通道不允许）。
13. **把软件包写入工艺/工程资产** → 拒绝。
14. **安装失败** → 旧版本继续跑，留痕。

审计：上传、下发、接收、确认、安装成功/失败；无包字节、无密钥、无日常密码。

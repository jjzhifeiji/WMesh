# 软件更新：云端、厂服务与客户端

> 讨论已拍板；工程冻结见 `软件更新-工程冻结.md`。服务层矩阵未跑通前不得当完成物。  
> 依据 `docs/平台架构核心需求.md`：Client 只连本厂；焊接进行中不中断；工程化优先、用标准件。  
> 不改核心需求正文。不改阶段 1～5 的资产允许/拒绝、归属与审计。

---

## 底线（无先后）

同时成立：

- **软件包不是工艺/工程。** 不进资产表，不走可复制、升档、闭包组包。
- **平板只从本厂拉。** Client 永不连 WAN；丢掉老 CDN 明文更新。
- **所有安装必须人确认。** 到包 ≠ 安装。无人确认则继续跑旧版本。
- **只向前。** 不允许发布、拉取或安装比该种类已接受版本更低的包；坏包靠再发更高版本。
- **库不单独发包。** Flyway SQL 打进对应服务镜像；换 app 启动后只向前迁库。升级包不含 postgres / OSS / alloy。

---

## 1. 本圈目标

本地构建按种类打程序包，上传到正在跑的 WAN。三种包分开发，不必一次齐。

| 种类 | 现在是什么 | 谁确认 | 谁落地 |
| --- | --- | --- | --- |
| **云端服务** `wan_service` | WAN 应用镜像 tar（API + 管理台 + 已嵌入的 Flyway） | WAN 管理员在云端管理台 | 本机 updater：`docker load` 后只重启 app |
| **厂服务** `factory_service` | 厂应用镜像 tar（同上） | 本厂超管在厂端管理台 | 本厂 updater：同上 |
| **客户端** `client_apk` | Android APK | 该平板当前登录的人 | 系统安装器 |

已认领且未注销的厂用现有 HTTPS 会话拉本厂需要的最高厂服务包和客户端包。WAN 发布厂服务包或 APK 时用 MQTT 通知有效厂立刻去拉。检查更新和确认只认本厂已收完整副本。WAN 不再按厂勾选下发，也不再给软件包做每厂/每机签名。

验收看：未确认不装、低版本拒绝、未认领/他厂拉不到、焊接中确认拒绝、摘要不对原件不动、迁库失败不对外、健康检查不过切回本机上一份。

---

## 2. 本圈不做

不改工艺/工程身份与闭包。不建 Client 工程、不向 Robot 下指令。不静默装、不强制装、不把旧版当产品回滚通道。不把更新包当加密工艺正文。不单独发 SQL，不把数据库或对象存储容器当升级目标。不在 MQTT 里推包正文。不做每厂签名快照、每机就绪信封、容器内自换自己的帮手。

首次装机仍用现在的全量 bundle（可含 db / oss / alloy）。日常升级只用 app 镜像或 APK。

---

## 3. 包是什么

一份发布是某一种类上一条只向前的版本，不是资产修订。

| 项 | 含义 |
| --- | --- |
| **种类** | `wan_service` / `factory_service` / `client_apk` |
| **版本** | 该种类自己的单调整数，只比较这个；另有给人看的版本名 |
| **摘要** | 包文件 SHA-256；对不上不得提示、不得装 |
| **字节** | 原样存放；厂端不得改 APK 再给平板 |

本地一次可以打齐三包，上传按种类独立；只发 APK 或只发厂包都合法。  
同一（种类, 版本）再上传：摘要相同 → 允许且幂等；摘要不同 → 拒绝，原件不动。  
该种类已有更高已发布或已安装版本时，再来更低版本 → 拒绝。未确认的低版本提示作废，改提示更高那份。

权限靠已有会话：WAN 管理员发布与确认云端；已认领厂会话拉厂包/APK；本厂登录者拉本厂 APK。完整性只靠摘要，不再另签软件包。

## 4. 怎么走

```text
本地：make test 通过 → 按需 docker save 只导出对应 app 镜像，或打 APK
  → WAN 管理员按种类上传（记种类、版本、版本名、摘要；字节进对象存储）

云端服务：
  WAN 管理台弹窗 → 管理员确认 → 只把 tar 和「待切换」落到本机盘
  → 本机 updater（不随业务 app 一起换掉）docker load，把当前标成 previous，只重启 app
  → 新进程起来先迁 WAN 库；探活失败则切回 previous，不记已装

厂服务包 / 客户端包：
  WAN 发布后向所有已认领有效厂推 MQTT 小指令（种类、版本、版本名；无字节）
  → 厂端通道收到后后台静默 HTTPS 拉到本厂对象存储；同一（种类, 版本）进行中或已完整则不重下
  → 通道一直连着也定时去问有没有更高版本，有则同样静默拉
  → 离线厂上线后再补拉
  → 检查更新 / 弹窗 / 确认只读本厂已收且摘要对得上的完整副本，不再去云端取包
  → 厂服务：超管确认后只落盘，本厂 updater 只换 app
  → 客户端：平板登录后问本厂最高 APK；人确认且空闲才走系统安装器
```

厂离线就先不拉；上线后再拉。平板只连本厂 HTTPS（安装走系统安装器），不得缓存 WAN 地址、厂服务镜像、他机包。

确认只表达「同意换」。真正换云端/厂端容器的是 updater，不是正在被换的 app，app 不挂 docker.sock。

## 5. 谁允许做什么

| 谁 | 允许 | 拒绝 |
| --- | --- | --- |
| **WAN 管理员** | 按种类上传；按种类看已发布版本；清掉不是最高也不是已装的旧包；看本机磁盘余量、对象存储已用、库占用和本机 app 镜像个数/占用；在该种类详情里让本机 updater 清无用 app 镜像 | 替厂或替平板点确认；上传未认领目标；改已发布版本的字节；删当前最高或已装版本 |
| **已认领且未注销的本厂** | 用厂会话拉最高厂服务包和客户端包 | 拉云端服务包；拉他厂副本；拉更低版本 |
| **未认领 / 已注销 / 他厂** | 无 | 读、拉、装任何包 |
| **本厂超管** | 看本厂已收的厂服务包/APK 并确认安装；清掉不是最高也不是已装的旧副本；看本机磁盘余量、对象存储已用、本厂库占用和本机 app 镜像个数/占用；在该种类详情里让本机 updater 清无用 app 镜像 | 改包字节；把包转给他厂；不确认就当已安装；确认云端服务；删当前最高或已装副本 |
| **本厂其他角色** | 无 | 确认厂服务或云端服务 |
| **平板当前登录的本厂有效账号** | 看本机待确认 APK 并确认安装 | 未登录安装；替他机确认；连 WAN 拉包 |
| **updater** | 只 load 已确认的 app 镜像并重启 app；失败切回 previous | 动 db / oss / alloy 容器；覆盖数据卷 |

没有明确许可一律拒绝。安装权威在当场点确认的那个人。

## 6. 确认与安装

**共同：**

- 包未完整到达、摘要不符 → 不弹窗，原运行版本不动，留痕。提示与确认不得改去读云端包。
- 弹窗必须能看：种类、版本名、版本号。确认前不替换正在跑的程序。
- 点「暂不更新」或关掉弹窗 → 不装；下次进入管理台 / 下次打开 App 仍提示，直到装上或被更高版本顶替。
- 确认后落地失败或探活失败 → 继续跑旧版本（本机切回 previous），允许再确认；不得自行改去装更低版本。
- 确认成功只表示同意换；记「已安装」必须等落地成功且探活通过。

**云端 / 厂服务：**

- 仅对应侧超管（WAN 管理员 / 本厂超管）在本机管理台确认。无人在线则包停在「待确认」。
- updater 只换 app。PostgreSQL 业务数据与对象存储不覆盖、不 down、不回滚。
- 新进程启动（厂侧含打开各厂库）按 Flyway **只向前**迁库；迁失败不得对外服务。
- 重启会短暂断开管理与通道；**不得因此远程停掉现场正在焊的 Client**。凭证未过期的这一焊继续。

**平板：**

- 不强制。当前登录者点确认才走系统安装器。
- 焊接进行中即使点确认 → 拒绝安装，提示焊完再确认。
- 各机各自确认，允许一厂暂时多版本并存。
- 节点凭证过期不得新装；已在焊的不因过期中断。

## 7. 驻留

- **WAN**：三类发布原件（元数据 + 对象存储字节）按种类分列；本机云端服务是否已确认安装。不持厂内人员库，不按下发名单存厂。
- **厂**：已拉到的厂服务包、客户端包只读副本按种类分列；厂服务是否已确认安装。不存云端服务包，不把他厂包当已到达。
- **平板**：只持已向本机提示的客户端包；不得缓存厂服务镜像、他机包、WAN 地址。
- **本机磁盘（云端/厂）**：待切换 tar、current / previous 镜像标签；updater 用，不进业务库。无用的旧 app 镜像可由 updater 清掉，不碰 db / oss / alloy。超管可看本机磁盘已用/剩余、本侧桶内对象占用、当前库占用和本机 app 镜像个数/占用，不含他侧盘。镜像占用由 updater 写入更新目录，app 不挂 docker.sock。清理入口在本机服务种类的详情里，与清旧包同一处。

该种类当前最高版本和已装版本不得删。比它们低的旧包允许删元数据和对象字节。源侧删了旧包，已拉到本厂的副本仍在，直到本厂自己清。

源侧后来再发更高版本，已安装的旧版本不自动覆盖，必须再提示、再确认。

---

## 8. 允许 / 拒绝

1. **未确认**：包已发布或已拉到 → 允许驻留；安装拒绝。
2. **WAN 管理员确认云端服务**：摘要通过 → 允许 updater 换 app 并迁 WAN 库；库与 OSS 不动。
3. **本厂超管确认厂服务**：同上，换本厂 app，各厂库向前迁。
4. **非对应超管确认该侧服务** → 拒绝。
5. **WAN 替厂确认 / 厂替 WAN 确认** → 拒绝。
6. **平板确认且空闲** → 允许走系统安装器。
7. **平板焊接中确认** → 拒绝；当前版本不动。
8. **未登录平板安装** → 拒绝。
9. **低版本**：该种类已有更高已发布、已拉到或已安装版本后再来更低 → 拒绝。
10. **同版本同摘要再发布或再拉** → 允许，幂等。
11. **同版本不同摘要** → 拒绝；原件不动。
12. **摘要不符** → 拒绝提示与安装；原件不动。
13. **未认领 / 已注销 / 他厂拉包** → 不得出现副本。
14. **厂会话拉云端服务包** → 拒绝。
15. **平板直连 WAN 或旧 CDN** → 拒绝。
16. **把软件包写入工艺/工程资产** → 拒绝。
17. **落地失败或探活失败** → 不记已装；切回 previous；留痕。
18. **升级时替换 db / oss / alloy 或单独下发 SQL** → 拒绝。
19. **只发布三种包里的一种** → 允许。
20. **清掉低于当前最高且不是已装的旧包** → 允许；对象字节一起删。
21. **删当前最高或已装版本** → 拒绝。
22. **清无用 app 镜像** → 允许 updater 清；current / previous 和 db / oss / alloy 不动。

审计：上传、拉取、确认、落地成功/失败、切回、清理旧包、清镜像；无包字节、无密钥、无日常密码。

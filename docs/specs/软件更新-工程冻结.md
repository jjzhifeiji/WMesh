# 软件更新工程冻结

> 业务对错以 `docs/specs/软件更新.md` 和 `软件更新-验收矩阵.md` 为准。  
> 本文件只冻结怎么落地；不改必须确认才装、只向前、Client 永不连 WAN。  
> 不新建 Client 工程、不测 MQTT、不向 Robot 下指令、不接系统 APK 安装器。
> 厂服务确认后真 `docker load` 换本机 app 容器；`go test` 仍不连真 Docker、不重启进程。

## 1. 目录

- 工程仍只有 `global/` 与 `factory/`。域文件：`store/update.go`、`service/update.go`、`httpapi/update.go`；WAN 另有通道帧 `software_update`。
- 验收：服务层矩阵仍直接调应用服务。管理台走 HTTP；通道回连补送与下发后推送同形。
- 两边各写 `internal/platform/softwaresign`（同算法，互不 import）。摘要仍用本侧 `digest` 的 SHA-256。
- 包字节进本侧 `blob.Store`（测试用内存）；**不进** `assets`，不走内容租约/WM2。本圈通道帧可带正文，短命拉取下一圈。
- 厂服务包是 Docker 镜像 tar（含 API、管理台、Flyway 脚本）。确认后 API 只写 tar 并拉起一次性帮手；帮手 `docker load` 成功才记已装，再换 app 容器。数据与 OSS 不覆盖、不 down。测试默认空安装器，不连真 Docker。
- 迁库实现在两边 `internal/platform/migrate`：进程内执行 Flyway 版本化 SQL，不另起 Java。禁止 down。

## 2. 库

WAN：

- `wan_signing_keys`：全表一行 Ed25519；私钥不进审计。首次发布时生成。
- `software_releases`：主键 `(kind, version)`；种类 `factory_service` / `client_apk`；版本 ≥1；摘要 32 字节；对象键；WAN 签名；版本名。不含包字节。
- `software_distributions`：主键 `(kind, version, factory_id)`；同一份再下发幂等。目标厂必须已认领且未注销。

厂：

- `wan_trust`：全表一行 WAN 公钥。通道首次送达可按快照公钥登记一次；对不上则拒绝。
- `software_replicas`：主键 `(kind, version)`；版本名、摘要、对象键、WAN 签名；无包字节。不得改已收修订的摘要/签名。
- `software_state`：按种类一行，记录本厂已确认安装的厂服务版本；未装为 0。客户端安装版本只在本机袋，不进厂库。

仍不准出现他厂包、厂内人员明细进 WAN、把软件包插入 `assets`。

## 3. 快照与签名

两边同名字段（不共用包）：

| 字段 | 含义 |
| --- | --- |
| `kind` / `version` / `versionName` | 种类、单调整数、给人看的版本名 |
| `digest` | 包文件 SHA-256 |
| `signature` | WAN 对下方原文的 Ed25519 签名 |
| `wanPublicKey` | 验签用公钥，须与厂内 `wan_trust` 一致 |
| `targetFactoryID` | 目标厂 |
| `body` | 本圈通道可带正文；短命拉取下一圈，语义不变 |

签名原文（两边同算法）：`"wmesh-software-v1" || kind || 0x00 || version uint64 大端 || digest || 目标身份 16 字节`。  
WAN→厂：目标身份 = 工厂 ID。厂→平板就绪信封：目标身份 = 该 Client ID，改用本厂签发钥签。

低版本：该目标已有更高**已下发或已安装**版本 → `revision is not strictly newer`。同版本同摘要再送 → 幂等。

## 4. 许可落点

| 谁 | 入口 |
| --- | --- |
| WAN 管理员 | `PublishSoftware`、`DistributeSoftware`、`ListSoftwareReleases`；HTTP 发布/下发；无确认入口 |
| 夹具 / 通道 | `AcceptSoftwareDelivery`、`SetWANPublicKey`、`ReadyClientUpdate` |
| 本厂超管 | `ConfirmFactoryUpdate`（仅 `factory_service`）；`PendingFactorySoftware`；管理台弹窗 |
| 本机袋当前登录者 | `ConfirmClientUpdate`（仅 `client_apk`） |

`ConfirmFactoryUpdate` 调安装器成功后才写 `software_state`；失败保持旧版本。不碰库与对象存储数据，不改本机袋焊接标记。  
`ConfirmClientUpdate`：未登录、焊接中、节点凭证不允许新开、低版本、厂签/摘要不对 → 拒绝；成功只改袋内已装版本。

服务层无：静默安装、下发旧版回滚、Client 拉 WAN、把软件包写入 `assets`。

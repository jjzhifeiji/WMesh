# 资产治理验收矩阵（规格圈冻结）

> 权威语义仍以 `docs/specs/03-资产治理.md` 为准。  
> 本文件把 §10 十八条冻成可独立判定的场景：条件 → 允许 / 拒绝 → 归属 → 审计。  
> 不连真设备，不测协议、界面、下发、打包、内容签名算法。  
> 第 7 圈必须按本表自动化跑通后，资产治理才能纳入基线。WAN 编号在 `global/server/internal/service`，厂内编号在 `factory/server/internal/service`。

未写归属的场景，归属为“无新资产 / 原件不变”。

## 歧义冻结（只补会分叉的点）

1. **本圈不建 Client 进程。** 个人级由厂内应用服务写入，夹具带创建人与工作上下文，语义等同 Client 产生 Fact。不测 HTTP / MQTT / 真设备。
2. **账号体系个人资产桩不动。** 本圈另建工艺/工程；桩仍只跑 01 矩阵。
3. **内容是不透明字节。** 不解析电流电压等行业字段，不做等级换算。设备 `processPath` 文件名不是身份。
4. **修订从 1 起，只向前。** 改显示名、内容、可复制、状态都升修订。写入（新建除外）必须带期望修订；对不上 → 冲突拒绝，原件不变。
5. **升档第一次 = 复制新身份。** 新修订从 1 起；记下源身份+源修订。源的级别、内容、修订、可复制都不改。同一源再升：正文摘要相同则返回已有条目且不升修订；摘要变了则覆盖该条目（身份不变、修订升高、源修订跟上）。不自动连带升档依赖工艺。
6. **升档调用不回个人正文。** 本厂有效账号可对个人级执行升档；读正文 API 仍仅创建人。
7. **默认可复制。** 个人级、厂级制作时为是；WAN 制作平台级为否；个人升厂级后新条目为是；厂级升平台级后新条目为否。
8. **可复制随时可改。** 未停用即可是↔否；停用后不得改。平台级与厂级同一套。
9. **状态。** 新建即草稿。草稿→可用允许；可用→停用允许；停用→可用允许（启用）。停用后不得改内容、不得升档、不得被新依赖。未被工程依赖的可物理删除；仍被 `deps` 引用的拒绝删除。
10. **谁制作。** 个人级、厂级：本厂有效账号（须能选定工作上下文）。平台级：仅 W。个人级正文仍仅创建人。
11. **工厂超管。** 可查、制作、升档本厂厂级；不可读他人个人正文；不可写平台级。
12. **工程依赖。** 只认稳定身份+修订。个人级工程：自己的可用个人级工艺，或本厂可用厂级工艺。厂级工程：本厂可用厂级或个人级工艺，以及已到达的平台级。平台级工程：只平台级可用工艺。草稿、停用、他厂、修订不符、摘要不符一律拒绝。
13. **已存工程不漂移。** 被依赖工艺后来升修订，原工程仍钉旧修订；完整性仍按所钉修订的摘要检查。
14. **跨厂。** 厂库互不可见。相同内容在厂 B 新建 = 新身份，不继承厂 A 身份。WAN 升档厂 A 厂级时，夹具把该厂快照交给 WAN（不测协议），WAN 库只留下新平台级。
15. **完整性。** 夹具可把已落库内容改脏；再读取当有效、使用、升档或当作依赖 → 拒绝。
16. **没有明确许可就拒绝。** 本圈无下发，厂库不存平台级副本，厂级工程不得依赖平台级工艺。

## 本圈规格完成定义

上表覆盖 §10 每一条，判定式统一为“条件 → 允许 / 拒绝 → 归属 → 审计”，歧义已按上文冻结。  
第 2～6 圈只实现能支撑本表的最小能力；第 7 圈按编号 1.1～18.2 全跑通后，才能把资产治理纳入基线。本阶段不做管理端与协议。

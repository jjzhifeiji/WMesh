# 第三圈规格：工艺与工程的身份、变更、归属与升档

> 前置：`01-账号体系.md`、`02-节点身份与离线授权.md` 已完成并通过验收。  
> 依据 `docs/平台架构核心需求.md` §1、§3、§4、§5、§7.5、§7.6。  
> 验收展开：`03-资产治理-验收矩阵.md`。落地：`03-资产治理-工程冻结.md`。

---

## 1. 本圈目标

工艺和工程成为可治理资产：有稳定身份、可判定的变更、明确归属与级别，并可按规则复制升档；内容损坏或跨厂冒用能被拒绝。  
本圈只定「是哪一条、谁的、哪一修订、能不能升、依赖是否对得上」；不打包、不下发、不激活。

---

## 2. 本圈不做

账号、组织、节点凭证、人员离线授权的既定语义不在本圈重做。  
不做下发、缓存、激活、工程闭包打包（下一阶段）；不做点云/图片、本地状态、工件主数据、Job/Task；不建 Client 进程、不测协议、不规定内容签名算法、不发明设备里没有的工艺业务版本号。  
账号体系里的个人资产桩仍只服务归属验收，不升级成真工艺/工程。

---

## 3. 资产与级别

工艺（可复用配方）与工程（一次作业，含焊道及该份自有参数）共用同一套治理字段，不拆两套模型：

| 项 | 含义 |
| --- | --- |
| **稳定身份** | 不可复用；显示名、文件名、路径都不是身份 |
| **所属** | 平台 / 本厂 / 创建账号（个人级同时属本厂） |
| **创建人** | 谁做出这一条 |
| **级别** | 平台级 / 厂级 / 个人级 |
| **状态** | 草稿 / 可用 / 停用 |
| **可复制** | 可否被上一级复制升档（不改原件） |
| **修订** | 同一身份上单调升高的变更号；用来判冲突、钉死依赖 |

| 级别 | 谁制作 | 默认可复制 | 原件谁改 |
| --- | --- | --- | --- |
| **平台级** | WAN | 否 | 仅 WAN 追加修订；厂与个人不得改 |
| **厂级** | 本厂 | 是 | 仅本厂有权工艺工程师；WAN 与他厂不得改原件 |
| **个人级** | 现场人员（本圈用厂内夹具模拟 Client 产生 Fact） | 是 | 仅创建人；停用账号后不得再改 |

可复制只表示允许上一级复制出**新条目**。不可复制的不得升档；不得因为「已经给过别人用」而把可复制从否改成是。

---

## 4. 身份、修订与完整性

- 新建一条资产就发一个稳定身份，修订从 1 起。改显示名、改内容、改可复制、发布/停用，只要改了已落库字段，就必须升高修订。
- 写入必须带**期望修订**（新建除外）。对不上 → 变更冲突，原件一字不改。
- 升档得到的新条目是新身份，修订从 1 起，并记下源身份与源修订；源条目不改。
- 每条修订登记内容摘要。读出或升档时摘要对不上 → 视为损坏或篡改，不得当有效资产使用或升档。本圈用摘要判定完整性，不规定签名算法。
- 设备明文里的工艺名、`processPath` 等只是内容或显示，不能当平台身份。

---

## 5. 状态

- **草稿**：可改内容与可复制；不得被工程依赖；不得升档；不得当作已授权可用资产使用。
- **可用**：可被获准方使用、可被工程依赖、可复制者可被升档。
- **停用**：不得改内容、不得升档、不得被新工程新依赖；已被引用的历史依赖仍指向原身份+修订，不重写。不得物理删除。
- 草稿可改为可用；可用可停用。本圈停用后不得再改回可用（要用就按规则复制出新条目或新建）。

仅草稿可把可复制从否改为是。可用后只允许从是改为否（收紧），不得放宽。

---

## 6. 谁允许做什么

- **WAN 管理员**：制作、维护平台级；把可复制且可用的厂级复制为平台级。不得制作厂级/个人级，不得改厂库原件，不得读取个人级原件。
- **本厂工艺工程师**（Factory 作用域，或组织作用域覆盖该资产创建路径）：制作、维护本厂厂级；对本厂可复制且可用的个人级执行升档（服务端复制，调用方不拿到个人原件正文）。
- **创建人**：在选定工作上下文中产生个人级；只有本人可读个人级正文、改自己的未停用个人级。
- **工厂超管、组织管理员/负责人、审计员、操作员**：不因职务自动获得个人级正文。操作员本圈只读已授权的**可用**厂级元数据与内容，不得制作、改、升档。
- 工厂超管须遵守级别与保密：不能仅凭超管身份读个人原件或把个人级升档。

没有明确许可一律拒绝。他厂身份在本厂一律拒绝。

---

## 7. 升档、汇聚与保密

- 个人级不上收则不在厂内共享：他人不得当厂级使用，也不得读正文。
- 厂内可按审计汇聚看到个人级**元数据**（身份、创建人、路径、级别、状态、修订），这不等于共享或已升档。
- 升档个人级 → 新厂级：默认可复制为是；所属本厂；创建人记为执行升档的工艺工程师。
- 升档厂级 → 新平台级：默认可复制为否；所属平台；创建人记为 WAN 管理员。厂级原件仍只在该厂。
- 平台级不再上收。不可复制、草稿、停用、摘要不符、他厂源 → 升档拒绝。
- 停用创建人或改其组织分配，不得删除、改写或转走其个人级；升档仍只复制出新条目。

---

## 8. 工程与工艺依赖

工程必须声明所依赖工艺的**稳定身份 + 修订**。工程自有参数（轨迹、多层、包角等）只属于这一份工程，升档或复制工程时不得另生成工艺身份。

引用时必须同时满足：工艺存在、状态为可用、修订吻合、摘要完整、调用方已获准使用该工艺。否则视为依赖缺失或错配，拒绝。

| 工程级别 | 允许依赖 |
| --- | --- |
| 个人级 | 创建人自己的可用个人级工艺，或本厂可用厂级工艺 |
| 厂级 | 本厂可用厂级工艺 |
| 平台级 | 平台级可用工艺 |

升档工程时不自动连带升档工艺；目标级别下每条依赖必须已经满足上表，否则拒绝。  
工艺后来升高修订，已存工程仍钉在声明的旧修订，不自动跟上；要用新修订必须显式改工程（带工程自己的期望修订）。

本圈无下发，厂级工程不得依赖「尚未到达本厂的平台级」。

---

## 9. 驻留

- WAN 只持平台级主数据与升档审计；不持各厂个人级原件，也不把厂级原件收成 WAN 主数据（升档只留下新的平台级副本）。
- 每厂库只持本厂厂级与本厂个人级汇聚。看不见他厂厂级/个人级。
- 本圈厂库不存平台级副本（下发后再存）。

---

## 10. 验收

以下均须能用“给定条件 → 允许 / 拒绝，并产生何种归属与审计”判定，不连真设备、不测协议。  
可执行场景见 `docs/specs/03-资产治理-验收矩阵.md`。

1. **稳定身份**：创建工艺或工程得到不可复用身份；改名、改内容、升档出的新条目都不改写原身份。
2. **修订冲突**：持旧修订写同一条 → 拒绝，原件不变；持当前修订写入 → 允许，修订升高。
3. **状态**：草稿不可依赖、不可升档；可用后可依赖、可按规则升档；停用后不得改内容、不得升档、不得被新依赖。
4. **平台级制作**：WAN 创建平台级，默认可复制为否；厂侧或他厂改该原件 → 拒绝。
5. **厂级制作**：本厂有权工艺工程师创建厂级，默认可复制；操作员、他厂人员、WAN 代写厂库 → 拒绝。
6. **个人级 Fact**：夹具以本厂有效工艺工程师写入个人级；归创建人、本厂、创建时路径；默认可复制。
7. **个人保密**：创建人可读正文；超管、同事、WAN、他厂读个人原件 → 拒绝。
8. **升档不改原件**：可复制且可用的个人级，本厂工艺工程师升档为厂级 → 新身份；原件级别、内容、修订不变。
9. **不可复制不得升档**：可复制为否，或草稿/停用，或摘要不符 → 升档拒绝。
10. **再升平台**：可复制且可用的厂级，WAN 凭快照复制为平台级（默认可复制否）；原厂级不变且仍只在该厂。
11. **跨厂隔离**：厂 A 的厂级/个人级，厂 B 读取、改写、升档、按同一身份引用 → 拒绝；在厂 B 用相同明文新建是新身份。
12. **WAN 不持个人原件**：从 WAN 查厂内个人级/厂级原件 → 拒绝或空。
13. **工程依赖**：声明的工艺身份+修订必须存在且获准；缺工艺、修订对不上、跨厂工艺 → 拒绝。
14. **工程参数不升格**：升档工程不另生成工艺；焊道/轨迹仍只属于该工程。
15. **汇聚不是共享**：厂内可见个人级元数据；未升档不得当厂级使用，升档调用也不得把个人正文返回给调用方。
16. **完整性**：内容与已登记摘要不一致 → 不得使用或升档。
17. **归属不漂移**：创建人改分配或停用后，个人级仍归原创建人与创建时路径；不得改挂。
18. **审计**：创建、改修订、发布、停用、升档、冲突、跨厂拒绝均有操作者、目标、结果；无密钥、无认证秘密、无内容原文。

---

# 同步审计工程冻结（阶段 5 · 工程圈）

> 业务对错仍以 `docs/specs/05-同步审计.md` 和验收矩阵为准。  
> 本文件只冻结怎么落地；不改 §8 与 1.1～6.1 的语义。界面、对外协议、真 Client、Robot、真实 OSS、完整审计台账仍不做。

---

## 1. 技术栈与目录

- 语言仍是 Go。工程仍只有 `global/` 与 `factory/`，**不新建 Client 工程**。待发队列、回连、激活许可放在 `factory/server/internal/service` 的本机袋上。
- 验收仍直接调本侧应用服务，不走 HTTP。本阶段编号全在厂内；WAN **不加表、不加汇聚入口**。
- 禁止两边互 import。共同能力继续放本侧 `internal/platform/`。
- 上传正文用进程内对象存根（`internal/platform/blob`）；`go test` 不依赖真实 OSS。摘要仍是 **SHA-256** 32 字节。

---

## 2. 数据库边界

- WAN 库本阶段不加与事实、上传、厂内审计汇聚相关的表。
- 每厂库本阶段可新增：`upload_records`（身份、种类、对象键、摘要、字节数、创建人、Client、首次汇聚时间）。**不存正文**。
- 阶段 1 `fact_stubs` **不改列、不迁数据**。汇聚按已有主键插入；冲突用应用层比对，不覆盖。
- 选库方式不变。跨厂隔离靠分库。

---

## 3. 本机袋增量

阶段 4 字段之外增加：

| 字段 | 含义 |
| --- | --- |
| `PendingFacts` | 待汇聚事实：产生端身份、创建人、发生节点、路径 |
| `PendingUploads` | 待汇聚上传：产生端身份、种类、正文、摘要、创建人 |
| `FailFlush` | 仅夹具：为真则本次汇聚失败，队列不动 |

入队在袋内追加。未 Flush 成功前厂库没有这些行。本圈待发只含事实和上传，不含工程/工艺同步状态（见 `厂端到控制器.md`）。

---

## 4. 服务入口

| 入口 | 规则 |
| --- | --- |
| `EnqueueFact` | 袋与本厂一致；`EvaluateOffline` 允许；角色为操作员。写入待发，不写厂库。 |
| `EnqueueUpload` | 同上；种类只许 `point_cloud` / `image`；摘要=SHA-256(正文)。 |
| `ConvergeIntent` | 必须已连网、本厂、Client 绑定未作废。拉取该 Client 最新节点凭证，`ApplyRuntime`（只接受更高修订）。 |
| `FlushPending` | 必须已连网、本厂。`FailFlush` → `sync retry required`，队列不变。否则按身份 `MergeFact` / 写入对象存根 + `MergeUpload`。 |
| `Reconnect` | 先 `ConvergeIntent` 再 `FlushPending`。 |

`ActivateProject` 已连网且根成员不是个人级时，须厂库对该 Client 的下发授权仍有效；未连网不查。这是 Intent 在激活上的落点，不改焊接/完整性规则。

`MergeFact`：无该身份则插入给定身份；已有且创建人/节点/路径相同则返回已有行；不同 → `asset integrity check failed`，已有行不改。

`MergeUpload`：同身份同摘要 → 返回已有记录；摘要不同 → 完整性失败。对象键=`工厂身份/种类/上传身份`。

业务错误：

| 错误 | 文案 | 何时 |
| --- | --- | --- |
| 弱网 | `sync retry required` | 夹具注入的汇聚失败 |
| 完整性 | 沿用 `asset integrity check failed` | 同身份字段或摘要冲突 |
| 无许可 | 沿用 `forbidden` | 未连网、跨厂、错角色、未授权激活 |

阶段 1 `CreateFact` / `CreateOfflineFact` 不改签名、不改为入队。

---

## 5. 许可落点

| 谁 | 允许 |
| --- | --- |
| 操作员 | 本机许可内 `EnqueueFact` / `EnqueueUpload`；回连 `Reconnect` |
| 夹具 | 置 `FailFlush`；不得绕过服务改 `fact_stubs` 路径或上传记录正文 |
| 超管、审计员 | 只读查询已汇聚事实/上传记录（沿用既有只读）；不得入队 |

服务层无：把正文写入审计、按墙钟覆盖事实、物理删除上传记录、把上传送到 WAN。

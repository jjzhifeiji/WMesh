## 共用夹具

名称只用于读场景，验收必须按稳定身份引用。

| 对象 | 含义 |
| --- | --- |
| W | WAN 唯一管理员 |
| 厂 A / 厂 B | W 已创建的两家工厂 |
| SA-A / SA-B | 两厂已激活的初始超级管理员 |
| PE-A | 厂 A 有效工艺工程师，Factory 作用域 |
| PE-A-shop | 厂 A 有效工艺工程师，仅车间 OrgUnit 作用域，且已分配到该车间 |
| OP-A | 厂 A 有效操作员 |
| PE-B | 厂 B 有效工艺工程师，Factory 作用域 |
| Client-A1 / Client-A2 | 已生成本机身份、拟属或已属厂 A 的现场节点 |
| Client-B1 | 拟属或已属厂 B 的现场节点 |
| 本机袋 | 夹具本地持有物：本机密钥、信任材料、节点凭证、连通标记、进行中焊接标记、已缓存工程闭包、当前激活工程 |
| 工艺/工程 | 沿用阶段 3 最小资产：不透明内容字节 + 治理字段；工程依赖为工艺稳定身份 + 修订 |

闭包归属字段：工程稳定身份与修订、成员工艺各自的身份+修订+摘要、闭包摘要、级别与可复制（与源相同）、下发目标（厂或 Client）。副本不是新身份。

审计必有：事件身份、操作者稳定身份、Factory（WAN 动作为空或记目标厂）、动作、目标（工程身份与修订、成员工艺身份与修订、目标厂或 Client）、结果、时间来源。  
日志不得出现密码、私钥、令牌原文、资产或闭包正文原文。

未写归属的场景，归属为“无新副本 / 本机袋不变 / 原件不变”。

## 歧义冻结（只补会分叉的点）

1. **本圈不建 Client 进程。** 下发送达与激活是应用服务判定；WAN→厂、厂→本机袋由测试夹具写入（模拟送达，不测协议）。
2. **闭包不是新身份。** 下发复制的是原身份+修订的只读快照。升档规则仍按阶段 3，本圈无「下发即升档」入口。
3. **组包成员恰好是工程 + 声明依赖。** 零依赖工程允许，闭包仅工程自己。多塞未声明工艺或少塞已声明工艺均为拒绝。
4. **组包只读源侧该修订正文。** WAN 读 WAN 当前行；厂内读本厂当前行或已按（身份, 修订）送达的平台级副本。当前行已升离钉死修订 → 新组包拒绝。
5. **已送达快照不随源漂移。** 源侧再改内容或升高修订，已在厂库或本机袋的那份成员修订与正文不变。新修订是另一次下发。
6. **厂内平台级副本按（身份, 修订）并存。** 不是只留最新一条去覆盖旧修订。未送达的（身份, 修订）不得当已到达。
7. **下发授权与执行分开。** W 授权工厂收平台级并亲自下发。SA 授权本厂 Client 收某工程；PE 执行下发。OP、超管、组织负责人、审计员不得执行下发。
8. **厂级下发作用域。** PE 须覆盖该厂级工程创建路径（直属须 Factory 作用域）。已收平台级工程再下发到 Client，须 Factory 作用域工艺工程师。
9. **Client 只收工程闭包。** 工艺随闭包进入本机袋。WAN 可把可用平台级工艺单独下发到已授权工厂（供厂级工程依赖），不可把游离工艺单独下发到 Client。
10. **个人级不共享下发。** 不得授权、不得下发到其他 Client。创建人可在本厂 Client 上组包并激活自己的可用个人级工程。
11. **默认可复制不因下发改变。** 平台级否仍为否；厂级是仍为是。目标不得把副本可复制改宽，也不得把副本升档。
12. **缓存按工程份。** 本圈夹具默认每 Client 上限 2 份；SA-A 可改为 1 或其他 ≥1 的数。超上限拒绝新缓存，不自动撤已激活或焊接中的。
13. **同时只激活一份工程。** 未焊接时可切换（先取消当前激活再激活另一份）。焊接中切换或撤该份缓存 → 拒绝，本次继续。
14. **连通标记沿用阶段 2。** 已连网：停用、收回下发授权立即阻止新激活。未连网：本地没有的新意图不生效，已缓存且凭证未过期仍可按本机快照激活。
15. **双重许可。** 激活须节点凭证允许、该闭包已授权给本机且角色允许使用。资产细权 = 本机是否持有该闭包且级别/所属允许该人使用（操作员/工艺工程师用厂级或已下发平台级；个人级仅创建人）。
16. **重复下发幂等。** 同一工程同一修订对同一目标再下发一次 → 允许，目标仍一份，闭包摘要不变。
17. **内容仍是不透明字节。** 不解析行业字段。设备文件名不是身份。
18. **没有明确许可就拒绝。** 未授权厂、未授权 Client、未绑定、他厂、只拷文件、改脏摘要，一律不得当有效闭包使用。

## 本圈规格完成定义

上表覆盖 §10 每一条，判定式统一为“条件 → 允许 / 拒绝 → 归属 → 审计”，歧义已按上文冻结。  
第 2～6 圈只实现能支撑本表的最小能力；第 7 圈按编号 1.1～17.2 全跑通后，才能把工程闭包纳入基线。本阶段不做管理端与协议。  
第 7 圈已按两边 `TestMatrix04` 合起来跑通。

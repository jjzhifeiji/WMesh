## 底线（无先后）

同时成立：

- **厂→控制器全程密文。** TLS 只保护运输，不算已经加密下发。
- **控制器落盘无明文。** 工程/工艺正文只存信封；解封钥和明文只在内存。
- **工艺是独立资产。** 工程只引用工艺稳定身份，不得用文件路径当身份，不得把工艺参数嵌进工程正文。
- **人可以换机，设备必须是本厂的。** 控制器与机械臂绑死，不跟人绑死。

## 1. 对照：设备旧形态（不当目标）

旧工程（`project_data.json` / `multilayer_data.json`）用 `processPath` 指向工艺文件名或相对路径（如 `1焊角6.5mm以下.json`、`User/1K6.5mmD.json`）。工艺 JSON 没有 `id`。多层焊道里还有空的 `process: {}` 占位。

这不是身份。文件名可变、可重名、可换目录；厂端组包、删除保护、升档都无法钉死。

厂端已经按正确模型落地：工艺/工程都是稳定 UUID；工程 `deps` 钉 `{id, 修订, 摘要}`；组包下发只认这个。控制器侧必须跟上，不能再把 `device-date` 那套路径引用搬进本机袋。

---

## 2. 工艺与工程怎么引用

拆两层，不得两套真相：工程 `deps` 钉 `{id, 修订, 摘要}`；正文焊道只写 `processId`。禁止 `processPath`，禁止把电流电压嵌进工程。挂钩位置、旧字段对照与导入步骤见 `docs/specs/工程与工艺引用.md`。

## 3. 加密：两套钟，不要混

| 谁 | 钥从哪来 | 有效多久 | 超时怎样 |
| --- | --- | --- | --- |
| **厂服务** | WAN 租约 | 最长 24 小时；窗口内不停产 | 整厂服务停（探活与 WAN 通道除外）；密文行保留 |
| **控制器** | 登录或碰巧上线时厂端下发工程/工艺解封钥 | **进程还活着就一直有效**，持续离线也不断 | 退出或 App 销毁立刻清钥和明文；必须再登录才能领 |

厂服务超时停的是厂端。控制器已领到的内存钥不因厂租约到期而作废，已缓存且节点凭证未过期的焊接不中断。

内容租约管厂服务能不能开；节点运行凭证管设备能不能跑；人员登录管这人现在能不能在这台控制器领钥。三套分开。

### 3.1 明文允许出现在哪

| 位置 | 正文 |
| --- | --- |
| WAN 库平台级 | 明文 |
| WAN / 厂进程内存（组包、读、过站前） | 明文，用完清解包钥匙 |
| 厂库 `assets`、`asset_replicas` | 只有信封 |
| 厂 → 控制器通道与下发记录 | 密文；厂库下发记录无正文 |
| 控制器磁盘（Room） | 只有信封 |
| 控制器进程内存（已登录且进程存活） | 允许解出明文，只在内存 |
| 审计、列表、控制面 MQTT | 无正文 |

### 3.2 过站怎么封

库内信封不出站。厂 → 控制器另造一次性过站 DEK，到站用该控制器钥匙重封进本机袋，**不复用厂库信封**。他厂或未绑定设备抄走解不开。

登录或回连上线时把解封钥发到控制器内存。磁盘始终是重封后的信封。使用（激活/焊接）时在内存解开；用完清的是解包后的明文工作副本，解封钥在进程存活期间保持。

## 4. 控制器是谁、怎么连

控制器就是现场 Client（低信任）。只连本厂，永不连 WAN。网络极差、经常持续离线。

厂 ↔ 控制器：

- **控制面**：MQTT over TLS（Client 出站连本厂 Broker）
- **正文**：HTTPS 另拉/另传；控制面只推身份、修订、摘要、短命拉取凭据

人员登录走厂内账号认证（HTTPS），和节点通道令牌不是同一把。通道会话不当权限缓存。Broker 不当信任根。

登录必须是本厂有效账号。未认证不得领解封钥。

---

## 5. 注册：控制器绑机械臂，不绑人

控制器和机械臂一对一绑定。注册时控制器必须读到机械臂识别号，向厂端登记并与该臂绑死。没读到号、或绑的是别的臂，不得当这台设备用。换臂必须重新注册。

设备归哪厂由 WAN 定。本厂只认本库已接受、未作废的绑定。未绑定、他厂、绑定已作废 → 拒签、拒下发、拒登录领钥。

平台 Client 稳定身份仍由系统给出（不当显示名）。机械臂识别号与 Client 号是否同一值，见文末未决；无论是否同一值，登记都必须带上读到的机械臂识别号。

---

## 6. 登录、换机、多人

- 只能上**本厂已绑定**的控制器，不能上他厂或未绑定设备。
- **人不绑死某一台。** 本厂有效账号可以随时使用本厂任一已绑定控制器，随时更换。
- 一台控制器允许多个本厂有效账号来登（换人登）。
- **同一人厂端同时只保留一台设备的登录。** 在第二台登录成功后，厂端注销该人在旧机上的登录权限。
- **不管老设备当下怎样。** 不推送、不远程清钥、不停焊、不同步处理老设备。老设备进程还活着就按原内存钥继续跑，直到它自己退出或 App 销毁。它再连厂端做登录类操作，发现权限已无，必须重新登。

节点获准运行，不等于当前人员获准操作。最终许可仍是账号状态、角色作用域、资产所属与级别、厂策略、节点凭证的交集。

## 7. 本机存储

相对文件目录，本机袋用 **Room**。安全不靠换容器，靠信封 + 会话钥。

加固：

- **SQLCipher** 整库加密。口令 = 登录/上线领到的解封钥，只在内存。进程死了库打不开，必须再登录。
- **禁止**用系统 Keystore（或等价本机长期钥）做成开机/重启自动解库。
- 关备份（`allowBackup=false`）。解封钥、工艺/工程明文不准进表、不准进日志、不准进审计。
- 库内只存闭包信封与必要元数据（身份、修订、摘要、显示名、状态）。不得再存一套明文工艺文件树。

拷走库文件但没有内存钥 → 打不开。一期仍不抗 Root 掏开着的进程内存。

## 8. 谁允许做什么（本文件新增的）

- **本厂有效账号**：在本厂已绑定且已读到机械臂识别号并完成注册的控制器上登录；登录或上线成功后领取该机已授权闭包的解封钥到内存。可随时换到本厂另一台已绑定控制器登录。
- **同一人第二台登录**：允许；厂端只保留新登录，作废旧登录。执行方不必通知旧机。
- **未登录 / 退出 / App 销毁**：内存钥与明文销毁。未再登录不得解正文。持续离线且当时连不上厂端 → 领不到钥，开不了正文。
- **他厂账号、未绑定控制器、未读到机械臂识别号**：拒绝注册、拒绝登录领钥、拒收下发。
- **厂端工艺工程师 / 超管**：下发与授权仍按工程闭包规格；不得因为已经下发就把不可复制改成可复制，也不得因此把平台级正文展示给厂端人员。

---

## 9. 不做

- 不把 `processPath` 或工艺显示名当稳定身份。
- 不在控制器落盘明文工艺库。
- 不把厂库信封原样拷到控制器。
- 不把全厂账号库下发到控制器。
- 不因厂租约到期或换机作废旧登录而远程中断老设备正在进行的焊接。
- 一期不承诺抗 Root 掏内存、虚拟机整机快照还原后再用那份内存钥。

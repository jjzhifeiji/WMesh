# 第一圈规格：账号、组织与权限

> 依据 `docs/平台架构核心需求.md` §3、§4、§5、§6、§7.2。  
> 本圈先完成 WAN 管理入口与 Factory 账号体系；不依赖 Client、Robot 或真实设备。

---

## 1. 本圈目标

WAN 只用一个全局管理员完成工厂初始化；每个 Factory 收到一个初始超级管理员账号后，自行建立人员账号、自定义组织层级和厂内权限。  
人员账号固定属于 Factory，可按本厂需要分配到任意自定义组织节点；业务事实保存发生时的组织路径，供后续统计和审计使用。

---

## 2. 本圈不做

Client / Robot 身份、跨厂共享账号、多父节点组织图、自助注册、第三方登录/单点登录、自定义角色、字段级权限、统计指标与报表、密码算法、令牌格式、通信协议和界面。

节点运行凭证在账号体系通过验收后，随节点身份规格实现。

---

## 3. WAN 管理入口

- WAN 人员侧只有一个全局通用管理员账号，不提供其他 WAN 用户的创建、邀请或授权能力。
- 该账号只做全局治理、创建工厂、初始化工厂超级管理员、管理全局策略与平台级资产、查看全局审计。
- 该账号不得直接作为任何 Factory 的业务操作者，也不得代替 Factory 创建普通账号、自定义组织或厂内角色。
- WAN 为每个新 Factory 只初始化下发一个超级管理员账号；账号稳定身份从创建起即绑定目标 Factory，不能用于其他工厂。
- Factory 激活该账号时，必须建立不由 WAN 持有的日常认证秘密；具体激活与交付方式不在本圈规定。激活后，账号生命周期与厂内授权由 Factory 管理，WAN 只保留初始化与交付审计。
- WAN 管理员可修改自己的日常密码。忘记唯一 WAN 密码时，由运维用启动配置一次性覆盖哈希；不得因此增加第二名 WAN 管理员，也不得代设厂内密码。

WAN 管理员是全局高权限单点，登录及每个管理动作都必须单独审计。

---

## 4. Factory 人员与自定义组织

人员和组织分开建模：

```text
Factory
├── Person（人员账号，固定归属 Factory）
└── OrgUnit（自定义组织节点）
    └── OrgUnit（可继续任意层级）
```

### 4.1 自定义组织

- Factory 可自定义组织类型与名称，例如场地、车间、产线、工段、班组，不预置固定层数或固定组合。
- 每个 OrgUnit 必须指定本厂定义的组织类型，并且只属于一个 Factory。
- OrgUnit 可直接挂在 Factory 下，也可挂在本厂另一个 OrgUnit 下；每个节点至多一个父节点，层级深度不限。
- OrgUnit 不得跨厂挂接、挂到自己或自己的后代，组织结构必须保持为树，不能形成环或多父节点图。
- 组织类型、OrgUnit 和账号均使用不可复用的稳定身份；显示名称可修改，业务归属不得用名称充当身份。
- 已被人员分配、资产、事实、统计或审计引用的组织类型与 OrgUnit 不得物理删除，只能停用。
- 组织类型仍有有效 OrgUnit、或 OrgUnit 仍有有效子节点时不得停用；须先停用或调整下级。
- 停用 OrgUnit 不影响人员的 Factory 归属，已有分配保留为历史关系，但该节点不得再作为新操作的组织工作上下文。

### 4.2 人员分配

- 每个人员账号固定且只属于一个 Factory，不属于任何 OrgUnit 所有。
- 人员可不分配 OrgUnit，也可分配到本厂恰好一个有效 OrgUnit；已有有效分配时再分到另一节点 → 拒绝。
- 分配到子节点不要求另存其祖先节点成员关系；祖先路径由组织树确定。
- 组织分配只表达人员当前可选的工作位置或组织关系，不自动授予任何业务权限。
- 调整或取消组织分配只影响后续工作上下文，不改变账号身份及其 Factory 归属。

---

## 5. Factory 账号生命周期

账号状态只有 **待启用、有效、已停用**：

- 待启用：可预置角色，但角色不生效；不得登录或执行受保护操作。
- 有效：完成认证后，可在明确角色与作用域内操作。
- 已停用：不得建立新会话或新开受保护操作，历史归属、事实与审计保留。可再启用，不得物理删除。

工厂超级管理员可以：

- 创建、改名、停用本厂组织类型与 OrgUnit，并调整节点父级；
- 创建、启用、停用本厂账号，并重置本厂其他账号密码（默认密码为登录名+123456，直接有效；重置后旧密码立刻失效、改回该默认，不发激活码）；
- 设置、调整和取消人员的 OrgUnit 分配；
- 授予、收回本厂角色及其组织作用域；
- 向本厂其他有效账号授予 Factory 作用域的工厂超级管理员角色，避免初始账号成为厂内唯一管理入口。

本人登录后可改自己的密码。重置密码不收回角色；短暂没有该人的有效登录，不按最后管理员保护拦截，以便另一名超管帮人找回。

初始超级管理员激活后，Factory 必须始终至少保留一个“有效账号 + Factory 作用域工厂超级管理员角色”的管理入口；会使有效管理入口变为零的账号停用或角色收回必须拒绝。

每个自然人使用独立账号，禁止多人共用。登录名只须在本 Factory 内唯一；显示名、登录名和认证材料可变，账号稳定身份不变。账号一旦被业务或审计引用，不得物理删除或把稳定身份重新分配给另一人。

## 6. 固定角色与作用域

一期只使用固定角色：

| 角色 | 可用作用域 | 核心权限 |
| --- | --- | --- |
| **工厂超级管理员** | Factory | 管理本厂组织、账号、角色、厂级策略和全厂审计 |
| **组织管理员** | Factory / OrgUnit | 管理作用域内组织节点、人员分配与角色，查看相应统计和审计 |
| **组织负责人** | OrgUnit | 查看该节点及其子树的人员、统计和审计，不修改账号与组织结构 |
| **操作员** | Factory / OrgUnit | 使用已授权资产、产生运行事实、按策略上传现场数据 |
| **审计员** | Factory / OrgUnit | 只读查看作用域内审计、统计与必要元数据 |

本厂有效账号均可制作、维护工艺与工程（个人级正文仍只创建人）。不另设工艺工程师角色。

账号可有多个角色，许可取并集，但每个角色都必须带明确作用域。Factory 作用域覆盖本厂及其全部 OrgUnit；OrgUnit 作用域覆盖该节点及其当前子树，不覆盖父节点或其他分支；没有明确许可一律拒绝。

人员的 OrgUnit 分配不自动产生角色，角色也不自动建立人员分配。管理角色不自动获得个人资产内容访问权；工厂超级管理员也须遵守资产所属、级别和保密规则。授予者只能授予自己可管理范围内的角色。

---

## 7. 归属与统计口径

- 每次产生业务事实或个人级资产时，必须选定且只能选定一个组织工作上下文：人员当前分配的那个有效 OrgUnit，或“Factory 直属”。
- 选择 OrgUnit 时，账号角色必须允许该节点上的业务操作；选择“Factory 直属”时，账号必须有相应 Factory 作用域角色。
- 记录创建账号、所属 Factory、选定 OrgUnit，以及当时从 Factory 到该节点的完整祖先路径快照；“Factory 直属”的 OrgUnit 与路径为空。
- 人员最多分配一个 OrgUnit；本次事实只计入选定节点及其祖先路径。
- 统计使用事实发生时保存的组织路径，不通过人员当前分配或当前组织树反查历史。
- 人员调整分配、组织节点改名、换父级或停用后，只影响之后的新事实；历史资产、事实、统计和审计不迁移、不重写。
- 被停用的账号、组织类型和 OrgUnit 仍可作为历史统计维度查询。

本圈只确定统计维度和历史口径，不定义产量、工时、焊缝质量等具体指标。

---

## 8. 在线认证与审计

- 受保护的人为操作必须有已认证会话，会话绑定账号稳定身份、Factory 与当前角色作用域。
- 账号停用或角色收回后，在线新操作立即拒绝；旧状态不得覆盖新意图。
- 退出登录立即结束当前会话，但不等于停用账号。
- 账号、组织类型、OrgUnit、人员组织分配和角色的创建、变更、停用，以及认证成功/失败、受保护操作允许/拒绝都须审计。
- 审计至少记录事件身份、操作者稳定身份、Factory、OrgUnit 作用域与当时组织路径、动作、目标、结果和时间来源。
- 认证失败无法识别稳定账号时，记录来源与被声明的登录标识；不得记录密码、认证秘密或完整令牌。

## 9. 验收

以下均须能用“给定条件 → 允许 / 拒绝，并产生何种归属与审计”判定，不连 Client 或真设备，不测协议。  
可执行场景与歧义冻结见 `docs/specs/01-账号体系-验收矩阵.md`；实现与第 7 圈自动化以该表编号为准。  
落地选型见 `docs/specs/01-账号体系-工程冻结.md`。

1. **WAN 只有一个账号**：尝试创建第二个 WAN 用户或给普通人授予 WAN 权限 → 拒绝。
2. **工厂初始化**：WAN 创建厂 A 并下发一个绑定厂 A 的初始超级管理员；该账号用于厂 B → 拒绝。
3. **WAN 不代管**：WAN 管理员直接为厂 A 创建普通人员、组织类型、OrgUnit 或厂内角色 → 拒绝。
4. **Factory 自行扩展**：厂 A 超级管理员创建自定义组织类型、多层 OrgUnit、人员账号并授予角色 → 允许；全过程有审计。
5. **层级可自定义且无环**：建立“场地 → 车间 → 产线 → 班组”或其他深度 → 允许；跨厂挂接、多父节点、挂到自己或后代 → 拒绝。
6. **人员固定归厂**：厂 A 人员不分配 OrgUnit、或只分配一个厂 A OrgUnit → 允许；已有有效分配再分到另一节点、分配厂 B OrgUnit 或登录厂 B → 拒绝。
7. **分配不等于授权**：人员已分配目标 OrgUnit 但没有目标作用域角色 → 受保护操作拒绝。
8. **角色不等于分配**：人员有目标 OrgUnit 角色但未分配该节点 → 可做角色允许的管理操作，但不得把该节点选作本人的业务工作上下文。
9. **角色边界**：组织管理员管理其他分支、组织负责人修改组织、操作员管理账号、审计员修改业务 → 均拒绝。
10. **账号状态与管理入口**：待启用或已停用账号登录、新开受保护操作 → 拒绝；历史记录仍可查询。停用最后一个有效工厂超级管理员账号，或收回其工厂超级管理员角色 → 拒绝。超管重置本厂其他账号密码 → 允许；操作员重置 → 拒绝。
11. **组织停用保护**：组织类型仍有有效节点、或 OrgUnit 仍有有效子节点时停用 → 拒绝；先处理下级后 → 允许停用但不物理删除。
12. **只计选定上下文**：人员分配在节点 A，本次选择 A 产生事实 → 只计入 A 及其祖先路径，不计入其他节点。
13. **人员调整不漂移**：取消 A、改分配到 B 后，历史事实仍归 A 路径，新事实可归 B。
14. **组织调整不漂移**：OrgUnit 改名或换父级后，历史事实仍使用发生时路径，新事实使用新路径。
15. **个人资产不改归属**：人员调整组织分配或停用后，原个人资产仍保留原创建人与创建时路径，不自动转给管理员。
16. **Factory 直属单列**：未选择 OrgUnit 且持 Factory 作用域角色的人员产生事实 → 归“Factory 直属”，不计入任一 OrgUnit。
17. **审计完整且无秘密**：上述允许与拒绝均有操作者、作用域、目标、结果与时间来源；日志中无认证秘密。
18. **WAN 数据最小化**：Factory 扩展出的普通账号、自定义组织及认证秘密不进入 WAN；WAN 只保留工厂与初始化审计。

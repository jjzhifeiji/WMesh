# 资产治理工程冻结（阶段 3 · 工程圈）

> 业务对错仍以 `docs/specs/03-资产治理.md` 和验收矩阵为准。  
> 本文件只冻结怎么落地；不改十八条语义。界面、对外协议、真 Client 进程、下发、打包、OSS 存正文、内容签名仍不做。

---

## 1. 技术栈与目录

- 语言仍是 Go。工程仍只有 `global/` 与 `factory/`，**不新建 Client 工程**。个人级由厂内应用服务写入（夹具带创建人与工作上下文）。
- 验收仍直接调本侧应用服务，不走 HTTP。矩阵里 WAN 侧场景在 `global/server/internal/service`；厂内场景在 `factory/server/internal/service`。升档到平台级：厂内导出快照，测试夹具交给 WAN（同阶段 2 的「接受绑定」）。
- 禁止 `global/server` 导入 `wmesh/factory`，禁止 `factory/server` 导入 `wmesh/global`。快照字段两边按本文对齐，各写各的结构体。
- 共同能力继续放本侧 `internal/platform/`。内容摘要用 **SHA-256**（32 字节）；这是完整性比对，不是下发用的内容签名。算法以后可换，只要「摘要对不上即拒绝」不变。

---

## 2. 数据库边界

- WAN 库本阶段可新增：平台级工艺/工程（含正文、摘要、修订、可复制、状态、升档来源身份与源修订）。仍不准出现厂内人员、组织、角色、口令、个人级/厂级原件。升档来源身份只当溯源字段，不在 WAN 当可改原件。
- 每厂库本阶段可新增：本厂厂级与本厂个人级工艺/工程（同上治理字段 + 创建时组织路径）。仍不准存平台级副本、不准存他厂资产。
- 账号体系 `personal_asset_stubs` / `fact_stubs` **不动**，不改列、不迁数据。
- 选库方式不变：按工厂稳定身份打开该厂库。跨厂隔离靠分库，不靠查询时过滤。

---

## 3. 资产形态

工艺与工程同一张表（或本侧同构的两张表，字段必须一致），用 `kind` 区分 `process` / `project`。每条当前一行，**不保留历史正文**；工程依赖把当时的工艺身份、修订、摘要钉在工程自己的 `deps` 里。

当前行必须能回答：稳定身份、kind、级别、显示名、状态、可复制、修订、内容、内容摘要、创建人、所属厂（平台级为空）、创建时 OrgUnit 与路径（平台级为空）、升档源身份与源修订（非升档则空）、deps（工艺必须空）。

| 落库 | 级别只允许 | 创建人 |
| --- | --- | --- |
| WAN | `platform` | WAN 管理员 |
| 厂库 | `factory` / `personal` | 本厂人员 |

约束（迁移里写死）：

- 修订从 1 起，只向前；身份不复用。
- 状态只许 `draft` / `available` / `disabled`。
- 内容与摘要同在一行；摘要长度 32。夹具可只改内容列、不改摘要列，用来验完整性。
- 工艺 `deps` 必须空数组；工程 `deps` 为 `[{id, revision, digest}, ...]`。
- 不得物理删除。更新必须 `WHERE id AND revision = 期望修订`，匹配 0 行视为冲突，原件不变。

显示名不当唯一键。设备文件名不进表。

---

## 4. 写入、冲突与完整性

- 新建不算期望修订，落库修订 = 1，摘要 = SHA-256(内容)。
- 改显示名、内容、可复制、发布、停用都是一次更新：调用方带期望修订，成功则修订 +1。只改名也升修订；内容未变则摘要可不变。
- 读正文、升档、把资产当「可用」使用前：按库内内容重算摘要，对不上 → 完整性失败，原件不改。
- 业务错误（两边 `internal/platform/domain` 各写一份，文案相同）：`revision does not match`（冲突）、`asset integrity check failed`、`asset is not available`、`asset is not copyable`、`asset dependency missing or mismatched`。停用后改内容/升档/新依赖走 `asset is not available` 或已有 `forbidden`；不要复用节点凭证的 `revision is not strictly newer`。

可复制：草稿可任意改；可用后只许是→否；平台级新建即为否且不得改为是。

## 5. 升档快照

厂内 → 厂级：本厂服务内复制，新身份、修订 1、默认可复制是、级别 `factory`，源身份/源修订指向个人级；响应只给新厂级元数据，**不含**个人级正文。

厂级 → 平台级：厂内导出快照（测试夹具调用，不测协议），WAN 只收这份内存结构并写入**新的**平台级行。快照至少含：源身份、源修订、源厂身份、kind、显示名、内容、摘要、可复制、状态、deps（身份+修订+摘要）。WAN 校验摘要、状态可用、可复制为是后复制；默认可复制否。WAN 库不留下厂级原件行。

升档工程不自动升工艺。目标级别下每条依赖必须已经有对应条目：

- 个人 → 厂级：依赖须已是本厂可用厂级工艺，或仍是创建人自己的个人级（个人级工程升厂级时，个人工艺依赖一律拒绝，须先升工艺）。
- 厂级 → 平台级：每条依赖的源身份必须已有平台级条目，且其 `source_id` + `source_revision` 与快照 deps 一致；新工程 deps 改写为这些平台级身份及其当前修订。找不到 → 依赖错配。

没有「从工程参数拆出工艺」的服务入口。

---

## 6. 许可落点

- 个人级：`CreatePersonalProcess` / `CreatePersonalProject` 走既有工作上下文解析；仅创建人 `Read*Content`；改未停用个人级仅创建人。
- 厂级制作/改/升档个人级：有效工艺工程师，且 Factory 作用域或组织作用域覆盖**该资产创建时节点**（直属须 Factory 作用域）。工厂超管不因此可读个人正文，也不能升档个人级。
- 操作员：只读本厂**可用厂级**元数据与正文；不得创建、改、升档。
- WAN：仅管理员做平台级创建/改/发布/停用/收快照升档。查厂内个人级或厂级原件的入口拒绝或空。
- 服务层无「改挂归属」「物理删除」「把内容写进审计」入口。

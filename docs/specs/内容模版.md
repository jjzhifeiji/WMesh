# 内容模版：工艺 / 工程字段形状

> 依据 `docs/平台架构核心需求.md` §1：工艺与工程以设备已有明文为准；字段可随业务增减，不在核心需求里写死。  
> 不改阶段 1～5 的允许/拒绝、归属、升档与闭包组包。治理仍按正文摘要与修订；本圈只约束正文 JSON 的字段形状。

---

## 1. 本圈目标

云端维护**当前**内容模版：工艺一份、工程一份。**只有新建**按当前模版套字段；已有正文继续有效，改模版、改正文、升档、复制都不改写旧 JSON。

厂端拿到模版的方式与平台级工艺相同：WAN 组快照推到已认领工厂，厂库只读副本，用最高修订当当前模版。

---

## 2. 本圈不做

不发明设备里没有的工艺业务版本号。不改账号、节点凭证、闭包成员算法。不把模版当可复制/可升档的焊接资产。Client MQTT 仍未铺，本机袋不另存一份模版。

---

## 3. 模版

| 项 | 含义 |
| --- | --- |
| **类型** | `process` 工艺 / `project` 工程，各一份当前行 |
| **稳定身份** | 每类一个，不因改字段而换 |
| **修订** | 改字段形状则升高；只向前 |
| **正文** | 字段表（键、中文名、类型、单位、默认值、是否必填、嵌套） |
| **摘要** | SHA-256（字段表规范 JSON），完整性对不上不得用 |

只有 WAN 管理员能改模版。厂与个人不得改原件。没有草稿/停用：保存即当前。保存只写下发，不套已有资产。

字段类型：文本（`string`，原文字/数字）/ 枚举（`string` 加 `options`，原是/否）/ `object` / `array`。旧模版里的 `number`、`bool` 仍能套用。参数名保持行业用语。初始字段来自设备已有工艺/工程明文。

管理台按工艺/工程正文 JSON 导入导出（与设备明文同形）；不导出字段表。

---

## 4. 套用

**仅新建**工艺或工程时：按该类型当前模版套用，再算摘要、再落库。

- 缺的键：写入默认值（无默认则用类型零值）。
- 多的键：删除。
- 嵌套 object / array 同样套。
- 非 JSON 或根类型不对：从空对象或空数组开始再补。

改正文、复制、升档、改模版：不套用，旧 JSON 原样有效。已送达闭包快照不动。平台级只读副本不就地改写。

---

## 5. 厂端

与平台级工艺同一条通道：回连补送当前两份模版；云端改模版后向在线厂推新修订。厂库存 `(身份, 修订)` 副本，按类型取最高修订。收到副本不改已有厂级/个人级正文。

厂内**新建**：有副本则必须套用；还没有副本时先按原样写入。改正文不套。不得改副本，不得把模版写进 `assets`。

---

## 6. 谁允许

| 谁 | 允许 |
| --- | --- |
| WAN 管理员 | 读/改两份当前模版并下发；不改已有正文 |
| 本厂有效账号 | 读本厂已收模版副本；新建时按副本套用 |
| 其他人 | 拒绝 |

审计：改模版、新建套用、下发/接收；无正文原文、无密钥。

---

## 7. 验收

1. 云端改工艺模版加字段 → 已有平台级工艺正文不变、修订不变。  
2. 随后新建工艺 → 落库正文已套新模版（含新字段、无多余键）。  
3. 改正文、复制、升档不套模版，旧键保留。  
4. 厂收到更高修订模版副本后，已有厂级/个人级正文不变；之后新建才套。  
5. 非管理员改模版 → 拒绝。  
6. 摘要对不上的模版不得套用。  
7. 厂尚未收到该类型副本时新建 → 正文原样。

# 内容模版工程冻结

> 业务对错以 `docs/specs/内容模版.md` 为准。两边互不 import，字段对齐。

## 1. 目录

- 套用算法：各侧 `internal/platform/contenttpl`（同名同语义；字段类型含 `process`）。
- WAN：`store/template.go`、`service/template.go`、`httpapi/template.go`。
- 厂：`store/template.go`、`service/template.go`；接收走 `Closure.AcceptTemplateDelivery`。
- 验收：`package service_test`。

## 2. 库

- WAN `content_templates`：工艺 `kind=process` 仍一行；工程 `kind=project` 多行，每份有名称、字段 JSON、修订、摘要。
- 每份工程模版 JSON：`{"root":"object","fields":[...]}`；新建允许 `fields` 为空。
- 厂 `content_template_replicas`：主键 `(id, revision)`，工艺按类型取最高修订，工程按身份取最高修订；不得物理删除、不得改已收修订正文。
- 不把模版插入 `assets`，不放宽 `kind` 检查。

## 3. 通道

信封 `typ=content_template`，载荷为模版快照（身份、类型、名称、修订、字段 JSON、摘要、目标厂）。回连推工艺一份加全部工程模版；改某一份只再推那一份所在的当前清单。厂端失败只记日志，不断通道。

## 4. 写入

Service **只在 Insert 新建**正文前调用套用。Update / 复制 / 升档 / 改模版 / 接收副本都不改已有 JSON。  
工程套用：空数组起；按元素 `templateId` 套那一份对象字段；对不上的丢掉。  
工程模版：每份独立新建/编辑/删除；名称必填；字段完全自定义。

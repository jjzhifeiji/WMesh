# 工艺 / 工程编号工程冻结

> 业务对错以 `docs/specs/工艺工程编号.md` 为准。两边互不 import，字段对齐。  
> 不改阶段 1～5 的允许/拒绝、归属、升档、组包。本圈不建 Client 工程。

---

## 1. 目录

- 编号算法：各侧 `internal/platform/assetcode`（同名同语义：形态、校验、种类前缀）。
- WAN：`store` 发厂短码 / Client 短码 / `W` 编号；`service` 新建/复制/升档不收调用方编号。
- 厂：`store` 用本厂短码发号；收副本按成员自带编号入库；个人级汇聚若带编号则原样落。
- 通道：认领 `enrolled` / 握手 `ready` / `factory_state` 带 `factoryShortCode`；`client_bind` 带 `clientShortCode`。
- 验收：`package service_test`（`asset_code_test.go`），夹具直调应用服务。

---

## 2. 库

WAN：

- `factories.short_code`：`F`+两位，`UNIQUE NOT NULL`，建厂时发，不改、不回收。
- `clients.short_code`：`C`+四位，`UNIQUE NOT NULL`，登记时发。
- `origin_code_seq(kind, next_n)`：`factory` / `client` 计数，行锁加一。
- `asset_code_seq(kind, next_n)`：`process` / `project` 的 `W` 序号。
- `assets.code`：`UNIQUE NOT NULL`，正则 `^(GY|GC)-(W|F[0-9]{2}|C[0-9]{4})-[0-9]{6}$`。

厂：

- `factory_lifecycle.short_code`：可空，认领或握手写入后不改。
- `clients.short_code`：可空，随 `client_bind` 补齐。
- `asset_code_seq`：本厂自建序号（按种类）。
- `asset_codes(id PK, code UNIQUE)`：身份级编号登记，覆盖本厂自建与已收副本。
- `assets.code`：`NOT NULL`，与 `asset_codes` 同号。
- `asset_replicas.code`：可空（旧副本等下次下发）；有值则写入 `asset_codes`。同一身份多修订同号。

已有行迁移补齐：工厂/Client 按创建顺序发短码；已有资产按本端计数补号；已有副本不编造云端号，等下次闭包带上。不改 UUID、修订、正文、摘要、审计原文。

---

## 3. 发号

- 新建（含同级另存、第一次升档）：Store 在同一事务里加一计数再写入。调用方带编号 → 忽略（应用服务不把请求字段写入）。
- 厂库代写个人级：用本厂短码。未齐本厂短码 → `asset origin code is not assigned`。
- 汇聚个人级（夹具可直写 Store）：调用方给出合规编号则原样登记，不改号、不加本厂计数。
- 收平台级副本：成员必须带与云端相同的编号；同身份已有号必须一致；同号不同身份 → `asset code already exists`。
- 序号溢出或短码用尽 → `origin code exhausted`。
- 改名/改正文/状态：不改编号。

---

## 4. 通道与夹具

- 建厂认领信封带本厂短码；已认领厂 `ready` / `factory_state` 补齐。
- `client_bind` 带 Client 短码；厂端 `AcceptBinding` 可空（夹具），有值则写入。
- 闭包成员增加 `code`；组包从资产行带出。摘要算法仍只钉身份+修订+摘要+正文，不加编号。
- 厂内验收不连 WAN：夹具 `PutFactoryShortCode("F01")`（第二厂 `F02`）。HTTP 引导测同样补短码。

---

## 5. HTTP / 管理台

列表与详情带只读 `code`。创建/改名请求不得收编号字段。搜索可按编号精确匹配（前端过滤即可）。

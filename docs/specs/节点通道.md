# 节点通道：厂↔WAN、厂↔Client

> 依据 `docs/平台架构核心需求.md` §2、§3、§6：通信层只承载交互，不决定业务权威。  
> 不改阶段 1～5 的允许/拒绝、归属与审计语义。阶段 2～5 验收仍用夹具模拟送达，不测本通道。  
> 厂↔WAN 认领与节点分配已随阶段 2 基线落地。厂↔Client 的 MQTT、升档/下发元数据仍等后续圈；未铺之前升档/下发仍由夹具写入。

---

## 1. 冻结什么

两跳共用一套业务信封（两边各写同名字段，互不 import）。会话合同不同：

| 跳 | 传输 | 谁拨号 | 在线时 | 断线时 |
| --- | --- | --- | --- | --- |
| 厂 ↔ WAN | **WSS**（TLS 上的 WebSocket） | 厂出站连 WAN | 秒级推 Intent / 回执 | 双方 outbox 按身份+修订补送 |
| 厂 ↔ Client | **MQTT over TLS** | Client 出站连本厂 Broker | 同上 | 本机袋为准；凭证过期前可离线运行，回连再收敛 |

Client **只连本厂，永不连 WAN**。跨厂只走 WAN 改绑；旧厂绑定作废后不得再经该厂通道收发。

「实时」只保证对端在线时秒级送达。不能假装厂或 Client 断网期间，撤销已经进了对方库或本机袋。

---

## 2. 不做

- 不建 Client 工程、不向 Robot 下指令。厂↔Client MQTT 未铺。
- 不把 Broker / 反向代理当信任根；不把通道会话当权限缓存。
- 通道载荷不得夹带：厂内人员明细、组织、角色、日常密码、Client 私钥、闭包/点云全文、他厂数据。
- WAN 不接收厂内事实、上传正文或厂内审计（仍按同步审计规格）。
- 建厂引导共享密码只用于安装期 HTTP；日常通道不用这把密码。

---

## 3. 谁说了算

| 权威 | 谁说了算 | 通道上怎么走 |
| --- | --- | --- |
| 信任与跨厂绑定 | WAN | WAN→厂：绑定 / 改绑 / 作废；厂回执 |
| 厂级 Intent（凭证、下发授权） | 本厂 | 厂→Client：就绪元数据；Client 回执 |
| 运行事实、点云/图片 | 产生端 Client | Client→厂：入队后汇聚；正文不进 MQTT |
| 升档到平台级 | WAN 收快照后复制新条目 | 厂→WAN：快照就绪 + 按摘要另拉正文 |

通道只送达。应用层仍走本侧 Service：验签、修订只向前、摘要不符即拒绝、默认拒绝。

---

## 4. 控制面与正文分离

控制面（WSS 帧或 MQTT 消息）只推**小信封**：类型、稳定身份、修订、摘要、目标厂/Client、签发方签名。

正文（闭包成员、升档内容、点云/图片）走 **HTTPS / 本侧 OSS**，凭信封里的摘要与短命拉取凭据拉取或上传。控制面不塞全文，避免大包堵住绑定与收回。

同一（类型, 身份, 修订）再送一次 → 允许且幂等，目标仍是那一份。只接受更高修订；低修订不得覆盖。

双方各有 outbox：未获应用层成功回执前，消息不得丢掉。

### 4.1 厂 ↔ WAN（WSS）

厂出站连 `GET /v1/channel`。建厂时 WAN 只写名录并发**建厂码**（只显示一次，库里只存哈希），不反打厂内网。

认领握手：

1. 厂 → `enroll`（建厂码）
2. WAN → `enrolled`（工厂身份、初始超管身份/登录名/显示名）
3. 厂本地建库、写入超管并当场设密码
4. 厂 → `claimed`（本厂签发公钥）
5. WAN → `welcome`，作废建厂码

认领后厂端保持出站连接：下次用 `hello`（厂钥签 nonce）重连，约 15 秒一跳心跳。WAN 名录显示在线/离线、上线时间、离线时间、最近心跳；WAN 重启把残留在线标成离线。

此后同一套接字钉死该 `factoryId`。日常节点分配走此通道：WAN→厂 `client_bind`（身份、名字、修订、可选公钥），改厂时旧厂收 `client_void`。厂回连时按当前所属补送，同一修订再送一次幂等。

厂 → WAN：认领回执、本厂签发公钥、升档快照就绪、心跳。

WAN → 厂：节点分配/改分/作废（`client_bind` / `client_void`）、工厂资产授权/收回、平台级闭包（可用或停用修订）、删除撤回（`platform_retract`）。

### 4.2 厂 ↔ Client（MQTT）

厂 → Client：本厂绑定声明、节点运行凭证就绪、工程下发/收回就绪、闭包就绪（身份+修订+摘要+短命拉取）。

Client → 厂：回执、待汇聚事实元数据、上传就绪（种类+摘要，正文走本厂 OSS）、在线心跳。

Topic 必须按身份锁死，禁止用通配扫他机、他厂。建议形态（实现可同义改名，隔离语义不得放宽）：

```text
factory/{factoryId}/client/{clientId}/down   # 仅该 Client 可订
factory/{factoryId}/client/{clientId}/up     # 仅该 Client 可发
```

Broker 只部署在厂内（随 Factory 工程），WAN 不起 MQTT。

## 5. 防冒充

服务端不相信 Broker 或套接字「自称是谁」。必须同时具备两层，缺一层即视为通道未冻结：

| 层 | 管什么 | 管不住什么 |
| --- | --- | --- |
| 传输身份（WSS / MQTTS 握手） | 谁能建立这条连接 | 连上之后塞假 Intent、改 Topic |
| 业务信封签名（复用已有 Ed25519） | 这条绑定/收回/下发是否真由上级签发 | 连接本身是不是正主 |

密钥与绑定材料沿用节点身份规格：WAN 根钥、厂签发钥、Client 本机钥；绑定时登记公钥。通道身份不另造长期预共享密码。

### 5.1 握手（两跳同形）

1. 对端声明稳定身份（`factoryId` 或 `clientId`）。
2. 本侧查库：已登记、绑定未作废、指向本侧；否则拒绝并留痕。
3. 挑战–应答：本侧发随机 nonce，对端用本机/本厂私钥签名，本侧用已登记公钥验签。  
   或改为持有上级签发的**短命通道令牌**（含身份、所属厂、过期、权限）；过期或换绑升高修订后旧令牌失效。
4. 通过后，**该连接或 MQTT 会话只钉死这一个稳定身份**。之后帧/消息里自报的身份一律忽略。

鉴权用短命令牌或私钥证明，不用长期预共享密码。长期密码一泄漏，整跳通道失守。

### 5.2 WSS（厂连 WAN）

- 全程 TLS，Client（此处为厂进程）校验 WAN 服务端证书。
- WAN 把该套接字钉死为该 `factoryId`；不得借用该连接读写他厂 outbox。
- WAN→厂 Intent 带权威签名；厂应用层验签后再走「接受绑定 / 收副本」一类入口。
- 现有 `POST /internal/bootstrap` 只保留安装期/测试夹具；日常建厂用建厂码认领，不用引导共享密码当通道凭证。

### 5.3 MQTT over TLS（Client 连本厂）

- 全程 MQTTS；Client 只连配置里的本厂主机名，并校验 Broker（或厂端）服务端证书。
- Broker 认证材料与 5.1 同类（短命令牌或与绑定公钥挂钩的客户端证书）。认证通过 ≠ 业务许可。
- ACL：**一机只能 pub/sub 自己的 Topic**。无该 Client 绑定、绑定已作废、指向他厂 → 拒绝连接或拒绝订阅。
- 假 Broker：厂端验不了「Client 连的是不是真 Broker」——Client 必须校证书，且下行 Intent 必须能用**已预置的厂签发公钥**验签。假 Broker 只能转发，签不出厂 Intent。
- Broker 被攻破时，没有信封签名就会被伪造收回与下发。因此 MQTT ACL 是减损，信封签名才是权威。

### 5.4 应用层仍要做的

- Intent：验签发方、目标身份、所属厂、修订只向前。
- 正文：按库内/信封摘要重算，对不上 → 完整性失败，原件不改。
- 会话不当权限缓存：每次受保护操作仍按节点凭证、厂内账号状态、资产许可交集判定。
- 审计不得出现密码、私钥、通道令牌原文。

### 5.5 一期不承诺

现场 Root、从本机抽出 Client 私钥后再连、有权人员主动泄露。能做的是短命令牌、换绑升高修订、在线撤销收敛，不是防 Root。

## 6. 分库与工程边界

- `global/server` 不 import `wmesh/factory`；`factory/server` 不 import `wmesh/global`。信封字段两边对齐，各写各的结构体。
- WAN 库仍不准出现厂内人员、组织、角色、日常密码、厂级/个人级原件、点云正文。
- 厂库仍不准当 WAN 名录，不准存他厂 Client 私钥。
- 管理端人员 HTTP 会话与本通道分开：浏览器令牌不能当节点通道凭证；节点通道令牌不能当人员登录。

传输选型（厂↔WAN = WSS，厂↔Client = MQTT over TLS）、出站方向、信封与正文分离、握手钉死身份、MQTT 按机 ACL、Broker 不当信任根，以上已冻结。

# 节点身份工程冻结（阶段 2 · 已纳入基线）

> 业务对错仍以 `docs/specs/02-节点身份与离线授权.md` 和验收矩阵为准。  
> 本文件按当前落地冻结。不建 Client 工程、不测 MQTT、不做 Robot / TPM / 工艺工程内容签名。

---

## 1. 技术栈与目录

- 语言仍是 Go。工程仍只有 `global/` 与 `factory/`，**不新建 Client 工程**。本地验证放在 `factory/server/internal/service`（夹具持本机袋），WAN 绑定放在 `global/server/internal/service`。
- 验收仍直接调本侧应用服务，不走 HTTP。矩阵 `0.*` 在 WAN；`1.1`～`16.3` 在厂内（含本机袋判定）。
- 禁止 `global/server` 导入 `wmesh/factory`，禁止 `factory/server` 导入 `wmesh/global`。声明字段两边按本文对齐，各写各的结构体。
- 凭证签名用 **Ed25519**；这是节点运行凭证的完整性，不是工艺/工程内容签名。
- HTTP 只做会话与 JSON 适配，不得绕过 Service。管理端已落地：WAN `features/clients`（名录、分配、改分），厂内 `features/clients`（列表、改名、签发/撤销许可、当前使用人）。

---

## 2. 数据库边界

- WAN 库：Client 稳定身份、显示名、公钥（可空，首次上线再登记）、当前所属工厂、绑定修订、工厂签发公钥。仍不准出现厂内人员明细、组织树、角色、日常密码。
- 每厂库：本厂已接受的 Client 绑定（含显示名、当前使用人）、节点运行凭证与撤销/修订。仍不准当 WAN 名录，不准存他厂 Client 私钥。不存人员离线授权表（已删除）。
- Client 私钥只存在夹具本机袋，不进 WAN、不进厂库、不进审计。
- 选库方式不变：按工厂稳定身份打开该厂库。

---

## 3. 信任材料

- WAN 持信任根密钥；Factory 持本厂签发密钥；Client 持本机密钥。私钥不进审计。
- WAN 建档并分配后，经厂通道把绑定声明推到目标厂；厂端调用同一「接受绑定」入口自动落库，管理端不再手填身份、公钥或修订号。公钥可后补。换厂升高绑定修订；旧厂绑定作废后不得再签。
- 无有效本厂绑定不得签发。签发还须本机公钥已登记（32 字节）。验收夹具仍可直接调用接受绑定，不测通道。
- 本机袋至少含：Client 私钥与公钥、WAN 根公钥、本厂签发公钥、当前绑定声明、已接受的最高节点修订、可选节点凭证、连通标记、进行中焊接标记。

算法以后可换，只要「谁签发、签给谁、属哪厂、能否运行、起止、修订号」和矩阵行为不变。

---

## 4. 凭证与授权形态

节点运行凭证必须能回答：签发 Factory、目标 Client、所属工厂、能否运行、有效起止、授权修订号；由本厂签发密钥签名。

不签发人员离线授权。本厂有效账号默认能上本厂设备；登录核对本厂账号与密码，厂库记下当前使用人。

签发与撤销节点凭证只允许本厂有效超级管理员。未绑定、他厂、已作废绑定、公钥未登记一律拒签。

更新规则：只接受更高修订；旧的过期、已撤销或低修订不得覆盖新意图。

---

## 5. 本地判定与时间

- 判定入口是纯函数：给定本机袋、要做的动作、当前钟，返回允许 / 拒绝 / 继续（仅进行中焊接）。
- 已连网用注入的服务器钟，时间来源 `server`；未连网用注入的本机钟，时间来源 `local`。一期不抗改钟。
- 受保护操作须同时满足：本厂有效账号、节点凭证允许、资产桩允许。任一不允许即拒绝。
- 过期或撤销：不得新开；进行中焊接标记为真则该次继续。
- 离线产生事实桩时选定一个 OrgUnit 或 Factory 直属，写入发生时路径；回连不得按当前分配或当前树改写。
- 审计 `time_source` 允许 `server` 或 `local`。不得出现密码、私钥、令牌原文。

---

## 6. 管理端与厂↔WAN 通道

- WAN：登记设备、改名、分给工厂、改分到另一厂。改分升高绑定修订，并向旧厂推作废、向新厂推绑定。
- 厂内：只展示本厂已接受的设备；超管改名、签发或撤销运行许可。无公钥显示待上线，不能签发。作废绑定由 WAN 改分驱动，厂端不在管理端手动作废日常路径。
- 厂出站认领走 HTTPS 交厂钥；日常 `client_bind` / `client_void` 走 MQTT，规格见 `docs/specs/节点通道.md`。厂↔Client MQTT 未铺。

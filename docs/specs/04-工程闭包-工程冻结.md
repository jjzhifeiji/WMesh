# 工程闭包工程冻结（阶段 4 · 工程圈）

> 业务对错仍以 `docs/specs/04-工程闭包.md` 和验收矩阵为准。  
> 本文件只冻结怎么落地；不改 §10 与 1.1～17.2 的语义。界面、对外协议、真 Client 进程、Robot、OSS 存正文、内容签名仍不做。

---

## 1. 技术栈与目录

- 语言仍是 Go。工程仍只有 `global/` 与 `factory/`，**不新建 Client 工程**。本机缓存与激活放在 `factory/server/internal/service` 的本机袋上；WAN 授权与下发放在 `global/server/internal/service`。
- 验收仍直接调本侧应用服务，不走 HTTP。两边互不 import：WAN 下发返回内存闭包快照，厂内「接受送达」由测试夹具调用（同阶段 2 接受绑定、阶段 3 升档快照）。
- 共同能力继续放本侧 `internal/platform/`。成员正文与闭包摘要都用 **SHA-256**（32 字节）；这是完整性比对，不是下发用的内容签名。算法以后可换，只要「摘要对不上即拒绝」不变。
- 阶段 3 的 `assets` 当前行表、升档快照、个人资产桩、事实桩 **不改列、不迁数据**。平台级副本另表存放，不把 `assets.level` 放宽成 platform。

## 2. 数据库边界

- WAN 库本阶段可新增：平台级资产 → 工厂的下发授权、下发记录（资产身份、修订、目标厂、闭包摘要、成员身份+修订）。仍不准出现厂内人员、组织、角色、口令、厂级/个人级原件，也不存闭包正文。
- 每厂库本阶段可新增：按（身份, 修订）保存的平台级只读副本（含正文）、工程 → 本厂 Client 的下发授权、本厂缓存上限、下发记录。仍不准存他厂厂级/个人级，不准把平台级写进 `assets`。
- Client 缓存正文只在夹具本机袋，不进 WAN、不进厂库。厂库只记「曾向该 Client 下发过哪份工程修订」，不含正文。
- 选库方式不变：按工厂稳定身份打开该厂库。跨厂隔离靠分库。

## 3. 闭包快照

两边各写一份同名字段的结构体（不共用包）。内存快照至少含：

| 字段 | 含义 |
| --- | --- |
| `kind` | `process`（仅 WAN→厂的单条工艺）或 `project` |
| `assetId` / `revision` | 根资产身份与修订 |
| `level` / `copyable` / `status` | 与源相同；下发不改 |
| `targetFactoryId` | WAN→厂时必填 |
| `targetClientId` | 厂→Client 或创建人装个人级时必填；WAN→厂为空 |
| `members` | 见下 |
| `digest` | 整包 SHA-256，32 字节 |

`members` 恰好为：根资产自己 + 工程声明的每一条依赖（工艺 `deps` 为空则只有自己）。工程成员排第一，其余按 `deps` 声明顺序。不得多、不得少、不得换序后仍算同一包（换序会改变闭包摘要）。

每个成员含：身份、kind、级别、修订、状态、可复制、正文、内容摘要、deps（工艺必须空）。成员内容摘要 = SHA-256(该成员正文)，且必须等于源侧登记摘要 / 工程 `deps` 里钉死的摘要。

闭包摘要计算（两边同算法）：按 `members` 顺序拼接 `id 16字节 || revision uint64 大端 || digest 32字节 || content`，再 SHA-256。对不上 → 完整性失败。

组包规则：

- WAN 只读 WAN `assets` 当前行。当前行修订不等于钉死修订 → `closure is incomplete`。
- 厂内组厂级：厂级成员读本厂 `assets` 当前行；平台级依赖读 `asset_replicas` 的（身份, 修订）。读不到或摘要不符 → 缺失或串版。
- 个人级：创建人自己的个人级当前行 + 已获准的本厂厂级当前行或已到达副本。
- 夹具若改 `members` 的身份/修订/正文而不改闭合约束，服务必须拒绝，不得「按夹具说的照收」。

业务错误（两边 `internal/platform/domain` 各写一份，文案相同）：

| 错误 | 文案 | 何时 |
| --- | --- | --- |
| 缺失 | `closure is incomplete` | 声明成员读不到该修订正文 |
| 串版 | `closure revision mismatch` | 身份或修订被顶替 |
| 缓存满 | `client cache is full` | 再收将超过上限 |
| 完整性 | 沿用 `asset integrity check failed` | 成员或整包摘要不符 |
| 非可用 | 沿用 `asset is not available` | 草稿/停用仍拿去新组包、新下发、已连网新激活 |
| 无许可 | 沿用 `forbidden` | 未授权、错角色、跨厂、个人级共享下发 |

不要把缺失/串版折进 `asset dependency missing or mismatched`（那是阶段 3 创建工程时的依赖检查）。

## 4. 授权、送达与副本

WAN：

- `GrantFactoryAsset` / `RevokeFactoryAsset`：按资产稳定身份授权某厂；未授权不得 `DistributeToFactory`。
- `DistributeToFactory`：仅可用平台级；工艺或工程都走同一入口。组包成功则返回快照并写下发记录。同一（资产, 修订, 厂）再下发 → 允许，记录不新增冲突行（幂等）。
- 厂内接受：`AcceptPlatformDelivery`（夹具调用）。按成员插入 `asset_replicas`；主键 `(id, revision)`；已有且摘要相同 → 原样返回；摘要不同 → 完整性失败。不得更新已有副本的正文。

厂内：

- `GrantClientProject` / `RevokeClientProject`：仅本厂有效超管；目标必须是本厂已绑定且绑定未作废的 Client；资产必须是本厂可用厂级工程，或本厂已有副本的平台级工程。个人级一律拒绝。
- `SetCacheLimit`：仅超管；整数 ≥1。默认 **2**（迁移写入一行厂设置）。
- `DistributeToClient`：仅有权工艺工程师。厂级工程须作用域覆盖创建路径；平台级工程须 Factory 作用域。目标须已授权、已绑定；厂库最新节点运行凭证必须允许运行且未过期（在线用服务器钟）。组包后写入本机袋，并记下发记录（无正文）。
- 无「下发到另一厂」入口。把已收平台级当厂级升档或改可复制 → `forbidden`。

`asset_replicas` 约束：级别只许 `platform`；可复制必须为否；不得物理删除；无改内容/改可复制/升档入口。厂级工程依赖平台级工艺时，`assertFactoryProcessDeps` 须能按（身份, 修订）命中副本且摘要一致，否则仍走阶段 3 的依赖错误。

## 5. 本机袋缓存与激活

本机袋在阶段 2 字段之外增加：已缓存闭包列表、当前激活（工程身份+修订，可空）。不删 `AssetAllowed`（阶段 2 矩阵仍用桩）。

- 缓存份数 = 袋内不同**工程稳定身份**的个数。同一身份同一修订再下发 → 覆盖为同一份，摘要不变。同一身份更高修订闭包 → 覆盖旧份，仍占 1 份。
- 超上限 → `client cache is full`，袋不变。撤缓存：`UncacheProject`；已激活或 `Welding` 为真 → 拒绝。
- 创建人装个人级：`CachePersonalProject`，不走 Client 下发授权；快照 `targetClientId` 必须是该人已持人员授权的本厂 Client。他人授权/下发个人级 → `forbidden`。
- `ActivateProject`：袋内须有该闭包；本机 `ClientID` 须等于快照 `targetClientId`；整包与成员摘要复核；节点凭证与人员授权按阶段 2 判定允许；角色须为操作员或工艺工程师（个人级还须人员身份 = 创建人）。已连网时再读源状态：厂级读 `assets.status`，平台级读该副本 `status`；非可用则拒绝新激活。未连网不查库，只凭袋内快照。
- 同时只激活一份。未焊接切换 = 先取消再激活。焊接中切换或撤当前份 → 拒绝，袋内激活不变，焊接继续。
- 只拷 `members` 到另一袋（不同本机密钥/ClientID）→ 激活拒绝。
- 判定仍用夹具注入的钟：已连网 `server`，断网 `local`。

## 6. 许可落点（服务入口）

| 谁 | 允许的入口 |
| --- | --- |
| WAN 管理员 | `GrantFactoryAsset`、`RevokeFactoryAsset`、`DistributeToFactory` |
| 本厂超管 | `GrantClientProject`、`RevokeClientProject`、`SetCacheLimit` |
| 本厂工艺工程师 | `DistributeToClient`（作用域见 §4）；许可内 `ActivateProject` / `CachePersonalProject`（仅自己的个人级） |
| 操作员 | 仅 `ActivateProject`（厂级或已缓存平台级） |
| 夹具 | `AcceptPlatformDelivery`；不得绕过服务直接改副本正文当「有效送达」 |

服务层无：把闭包正文写入审计、物理删除副本、改副本可复制、把平台级插入 `assets`、Client 拉取 WAN、给 Client 下发游离工艺。

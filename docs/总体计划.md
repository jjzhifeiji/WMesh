# WMesh 总体计划（到可验证版本）

> 当前状态：账号体系服务层已基线；正在做 WAN/厂内 HTTP 与两套管理端，尚未开始阶段 2。  
> 仓库按两个工程分开放：`global/` 跨厂总控、`factory/` 厂内；各自只有 `frontend/` 与 `server/`，Go 模块和数据库编排只在 `server/` 内。  
> 推进方式：每阶段「规格 → 实现 → 验证 → 基线」；未验证不得当完成物、不得并入基线。  
> 需求依据：`docs/平台架构核心需求.md`。

---

## 阶段 1　Factory 账号体系

建立 WAN 单管理员入口，以及 Factory 超级管理员自助扩展的人员账号、自定义组织层级、角色、统计归属与在线审计。

- 规格：`docs/specs/01-账号体系.md`
- 验收：`docs/specs/01-账号体系-验收矩阵.md` 编号 1.1～18.3；不连 Client 或真设备、不测协议
- 阶段门：第 7 圈全跑通并纳入基线前，不推进任何后续阶段

实施小圈（可独立验收，未通过不进入下一圈）：

1. 规格圈：补齐歧义，冻结“条件→允许/拒绝→归属→审计”矩阵
2. 工程圈：技术栈、数据库、认证方式、稳定身份、迁移策略
3. 数据圈：Factory、账号、组织树、人员分配、角色授权、会话、审计模型与约束
4. 认证圈：WAN 单管理员、工厂初始化、激活、登录退出、账号状态
5. 权限圈：六种固定角色、Factory/OrgUnit 作用域、默认拒绝、最后管理员保护
6. 归属圈：用事实桩与个人资产桩验证工作上下文、路径快照、历史不漂移、完整审计
7. 基线圈：自动化跑通矩阵全部编号，通过后纳入基线

## 阶段 2　节点身份与离线授权

建立 Factory / Client 节点信任、Client 离线运行许可，并把已完成的 Factory 账号权限安全带到离线 Client。

- 规格：`docs/specs/02-节点身份与离线授权.md`
- 验收：该规格 §7 十六条；不连真设备、不测协议

## 阶段 3　资产治理

确定工艺 / 工程的稳定身份、版本、归属、升档与完整性。

- 验收：跨厂隔离、变更冲突可判定

## 阶段 4　工程闭包

实现工程与所依赖工艺的完整打包、下发、缓存和激活。

- 验收：不缺失、不串版

## 阶段 5　同步审计

实现弱网重试、幂等汇聚、Intent 收敛、上传记录。

- 验收：断网恢复、审计可追溯

## 阶段 6　集成版本 V0.1

部署 1 个 WAN、2 个 Factory、多个 Client，做端到端验证。

- 验收：在线下发、离线运行、撤销收敛、跨厂拒绝

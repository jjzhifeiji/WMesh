# 示教器 (ShiJiaoQi) 功能更新日志

## [近期更新] 细节优化与时序修复

### 1. 硬件手柄按键功能扩展
- **功能描述**：为游戏手柄的 `SELECT` 按键添加了快捷指令。
- **具体实现**：按下 `SELECT` 按键后，系统会自动向控制器下发两条控制指令：
  1. `Mode(1)`：切换至手动模式（指令下发后自带 50ms 延时保护）。
  2. `RobotEnable(1)`：设置机器人使能状态。
- **涉及页面**：主页面 (`MainActivity`) 与多层多道页面 (`MultiLayerActivity`)。

### 2. “长按继续”功能优化
- **功能描述**：在执行断点续焊（长按继续按钮）时，确保机器人处于正确的自动运行模式。
- **具体实现**：长按继续时，系统会优先发送 `Mode(0)` 指令切换至自动模式，随后再下发原有的 `WeldingStartReWeldAfterBreakOff()` 和 `RESUME` 恢复运行指令。

### 3. 解决控制指令并发乱序问题
- **问题描述**：在下发包含 `Mode(0)` 和 `Start` 组合指令时，控制器偶发响应顺序颠倒（先收到 Start 后收到 Mode(0)），导致运行状态异常。
- **修复方案**：将原本拼接在一起的一条组合指令拆分为两条独立指令，并在两次下发中间增加 `100ms` 的强制延时。确保控制器先执行模式切换，稳定后再执行启动。

### 4. 摆焊开始 (`WeaveStart`) 时序修正
- **问题描述**：多层多道功能中，摆焊指令在机器人尚未移动到起点时就被提前下发，导致动作逻辑不符合预期。
- **修复方案**：
  - 移除了批量脚本开头的全局 `WeaveStart(3)` 指令。
  - 在生成路径逻辑时，严格确保在非起点断点继续或首次运行到达起点（即生成了 `MoveL` 或 `MoveC` 运动指令）之后，再下发 `WeaveStart(3)` 指令。保证“先到达起点位置，再开始摆焊”。

### 5. 单层单道多焊道批量下发优化
- **问题描述**：在单层单道模式下激活多条焊道时，每条焊道都会独立发送一对 105（脚本声明）与 106（指令内容）指令，产生冗余并可能影响连贯性。
- **修复方案**：重构了 `sendBatchMoveLCommands` 方法，引入全局唯一的 `BatchCommandBuilder`。现已实现将所有激活焊道的指令一次性打包，通过单次 105、106 交互下发给控制器。

## [上一版本更新] 断点续焊重构与UI优化

### 1. 断点续焊（暂停/继续）底层逻辑重构
- **废弃旧方案**：移除了原有的重新计算路径方案。
- **引入新机制**：直接通过 8080 端口下发控制器的原生 `Pause` 和 `RESUME` 指令。
- **中断恢复闭环**：在触发“继续”前，针对焊接中断状态追加发送 `WeldingStartReWeldAfterBreakOff()` 重连指令；在触发“停止”时，追加发送 `WeldingAbortWeldAfterBreakOff()` 终止指令。

### 2. 状态反馈解析与显示
- **8083 端口解析**：根据控制器用户手册，精准计算出序号 69“焊接状态”所处的绝对字节偏移量（425、426）。
- **状态栏拆分**：在 UI 状态栏中，分别独立显示“焊接”和“电弧”的中断/正常状态，让用户对当前状态一目了然。

### 3. UI 交互与布局优化
- **长按防误触**：将“继续”按钮的交互方式从点击改为“长按继续”，有效防止误操作。
- **状态栏重排**：将原状态栏中的“焊长”、“时长”、“系统更新”三个功能项，移至右侧按钮列表的最底部。
- **暂停状态保持**：解决了点击暂停后，因收到 8083 端口“停止(1)”状态导致“继续”按钮消失的问题。现已增加对 `programState == 1` 与 `weldingBreakOffState == "中断"` 组合状态的判定，正确维持暂停 UI。

### 4. 底层网络通信同步优化
- **修复 105/106 乱序**：在 Socket 写入层引入 `sendBatchCommandSync` 阻塞式同步方法，并在 ViewModel 协程中强制 `delay(50)` 确保缓冲区顺序，彻底解决协程并发导致的 105 与 106 脚本指令乱序下发问题。
